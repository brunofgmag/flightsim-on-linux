SimConnect over TCP

Tested with SimConnect 12.2.0.0 on 15 October 2026. One command, with the simulator closed. Programs that live outside the simulator's prefix need it.

Why it is needed

A program in the simulator's prefix talks to the simulator through a named pipe. A program in another prefix, or a native Linux program, can't reach that pipe, so it uses TCP. The simulator's SimConnect.xml declares a static IPv4 port, 500 by default, and Linux doesn't let the simulator open a port below 1024.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply simconnect-tcp

If SimConnect.xml doesn't exist yet, start the simulator once so it writes the file, then run the command again. The command does two things:

  • moves the static IPv4 port to 5111 when it is below 1024, and keeps the original file in compatdata/2537590/flightsim-on-linux-backup/simconnect-tcp;
  • installs node-simconnect 4.2.1 into the project's cache folder when npm is present. Only the watchers that follow the loaded aircraft need it.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check simconnect-tcp

It reads the port in SimConnect.xml and fails when the port is below 1024. It changes nothing.

Who uses it

  • The programs of the add-ons prefix and Navigraph Simlink, which read the port from a SimConnect.cfg.
  • The aircraft watchers of the FSLabs A321 and the Maddog MD-80.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo simconnect-tcp

It puts the original SimConnect.xml back. node-simconnect stays in the cache folder.
