With an AI assistant

Assistants tend to answer Wine questions from memory, and those answers are often for another Proton, another add-on version or another machine. They do much better when they read your machine's state first and check each step. Whether they do that depends mostly on what you tell them at the start.

Chat assistants that can't run commands

This covers ChatGPT, Gemini, Claude and local models in a chat window. You run the commands, the assistant reads the output. The prompt below spells the rules out, which matters most with smaller models. Paste it at the start of the conversation:

I want to set up Windows add-ons for Microsoft Flight Simulator 2024 (Steam) on Linux
with the project at https://github.com/brunofgmag/flightsim-on-linux.
Its guide is at https://brunofgmag.github.io/flightsim-on-linux/ and a summary for you
is at https://brunofgmag.github.io/flightsim-on-linux/llms.txt.

Rules for you:
1. Before suggesting anything, ask me to run
   ~/flightsim-on-linux/bin/flightsim-on-linux doctor
   and read its output. Don't guess folder names; they differ on every machine.
2. Give me one step at a time. After each step, tell me which command shows
   whether it worked, and wait for its output.
3. Use only commands and settings from that guide. If you think something else
   is needed, say it is your own idea and why.
4. Never ask me for licence keys, passwords or files that contain them,
   such as the FSLabs CCLog.txt.
5. Never suggest editing an add-on's own files unless the guide does, and then
   tell me how to undo it first.

If your assistant can't open web pages, paste the page you are working from, for example Start here, after the rules.

Coding agents that run commands

This covers agents like Claude Code, Codex or Gemini CLI that work in a terminal on your machine. Open them inside the project folder. The repository has an AGENTS.md that these tools read on their own; Claude Code and Gemini CLI reach it through the CLAUDE.md and GEMINI.md next to it. It tells them to:

  • learn the machine first with bin/flightsim-on-linux machine --json and doctor --json;
  • fix the environment rather than the add-on, and say so before touching any add-on file;
  • install an add-on with addon install <id> <file> instead of a Wine command of its own, because that command refuses to start while anything holds the prefix;
  • ask before writing a menu entry or a service: addon shortcut writes under your home folder, and addon watcher also switches a user service on. Each has a command that takes it out again;
  • clear NoDefaultCurrentDirectoryInExePath when starting Wine by hand, because Claude Code sets it and Wine installers fail with it;
  • never touch licensing, never print licence keys, and never re-run an installer that spends an activation;
  • diagnose from a trace taken from the very start of the program, with WINE_MONO_TRACE=E:all for .NET apps;
  • prove each fix by reverting it and watching its check fail.

A good first request: "Read AGENTS.md, run the doctor, and tell me what is missing before changing anything."

Whether an agent asks before running a command depends on how you set it up. Keep it asking, and read what it proposes. Anything that installs, deletes or edits files in the prefix deserves a second look, and so does anything outside your home folder.

When the assistant is stuck

Open an issue with the output of bin/flightsim-on-linux doctor, the add-on and its version, and what you tried. Remove licence keys and account names first.
