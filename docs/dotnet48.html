.NET Framework 4.8

Tested with the .NET Framework 4.8 offline installer (ndp48-x86-x64-allos-enu.exe) on 18 October 2026. One command, with the simulator and every other program of the prefix closed. It is a base piece: it puts the framework into the prefix and writes no setting for any single add-on.

Get it

Microsoft's framework is free. The command downloads two files from Microsoft and checks both against pinned sha256 hashes before it uses them: the 4.8 installer, ndp48-x86-x64-allos-enu.exe, and the 4.0 installer, dotNetFx40_Full_x86_x64.exe. The second one is only opened to take Microsoft's mscoree.dll out of it. Neither file is part of this project, and both are kept in the project's cache folder (~/.cache/flightsim-on-linux/downloads), so the next run does not download them again.

The command needs 7z and cabextract on your PATH for the mscoree.dll step. If the cache folder's path is longer than 150 characters it stops before downloading: Windows installers inside Wine fail on paths over 260 characters, and Installing add-ons explains why. Set FSOL_CACHE to a shorter folder.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply dotnet48

Close the simulator and every other program of the prefix first; the ground rules say why installers run alone. The command skips any step that is already done:

  1. It installs .NET Framework 4.8. The prefix of Proton FS2024 reports Windows 11 (build 22000). On 18 October 2026, on the test machine, the 4.8 installer run as /q /norestart in such a prefix exited with code 0 and installed nothing. Its own log said that .NET 4.8 or later was already installed. So the command saves the Windows version keys (Windows NT\CurrentVersion in both registry views, and Version under HKCU\Software\Wine), switches the prefix to Windows 7 with winecfg -v win7, deletes the links Proton leaves in the v4.0.30319 folders, runs the installer with the fusion DLL set to builtin, and puts the keys back one value at a time. It stops if the result does not match what it saved. winecfg -v win10 is not a way back: it writes another build and another UBR and rewrites the 32-bit view. If an earlier run was interrupted, the next run gives the saved keys back first. It then reads clr.dll in both Framework folders and fails if it is not a 4.8 build.
  2. It puts Microsoft's mscoree.dll in system32 and syswow64. The command takes version 4.0.31106.0 out of the 4.0 installer and checks it against a pinned hash for each folder. The file it replaces, or the link to Wine's builtin, is kept first. A program uses Microsoft's file only when an add-on sets mscoree to native for it; every other program stays on wine-mono.
  3. It sets four registry values. mscoree stays builtin under HKCU\Software\Wine\DllOverrides, so no program gets Microsoft's by accident. InstallRoot under HKLM\Software\Microsoft\.NETFramework names the 64-bit Framework64 folder in the 64-bit view and the Framework folder in the 32-bit view. * is gac=n under HKCU\Software\Wine\Mono\AsmOverrides: with 4.8 in the Windows GAC, wine-mono would look there first and load Microsoft's WPF, and Axis and Ohs died at start with a MissingMethodException on the test machine. Before it writes, the command exports the keys it is about to change to .reg files in the backup folder.

The backup folder is compatdata/2537590/flightsim-on-linux-backup/dotnet48. A machine that ran the Fenix add-on before this one existed keeps its backups in flightsim-on-linux-backup/fenix-a320, and the command keeps using that folder until a dotnet48 one exists.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check dotnet48

It prints eight lines and changes nothing. Four look at the registry values above. Two read the product version of clr.dll in Framework64\v4.0.30319 and Framework\v4.0.30319 and want 4.8. Two compare mscoree.dll in system32 and syswow64 with the pinned hashes of Microsoft's 4.0.31106.0 files.

Who uses it

  • The Fenix A320 runs five of its programs on Microsoft's .NET. addon apply fenix-a320 runs this step first, then sets its own mscoree=native overrides.
  • The Maddog MD-80 runs MDClient on it, because on wine-mono MDClient keeps the wineserver busy. addon apply maddog-md80 sets the override once this is in the prefix.
  • SayIntentions.AI needs it for si_telemetry.exe, which cannot run on wine-mono. Without it the interface stays on its loading screen.
  • Axis and Ohs sets the same gac=n value itself and is not changed by this step.

Known problems

  • An installer exit code of 0 from the 4.8 setup does not prove anything in a Windows 11 prefix. The command trusts clr.dll, not the exit code.
  • The command does not change the Windows version for good. If it stops between the switch to Windows 7 and the restore, run it again: the first thing it does is give the saved keys back.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo dotnet48

It puts the original mscoree.dll back in system32 and syswow64 from the backup folder. .NET Framework 4.8 stays installed, and the four registry values stay: with 4.8 in the Windows GAC, taking gac=n away makes wine-mono programs load Microsoft's WPF and crash. The overrides that other add-ons set for their own programs are theirs to undo, and they ask for the Microsoft mscoree.dll that this undo takes away, so undo those first.
