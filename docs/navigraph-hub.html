Navigraph Hub

Tested with Navigraph Hub 1.2.24 on 31 October 2026. The Hub installs like any Windows program. One helper file inside it has to be replaced, or AIRAC cycles and plugins won't install, so this fix changes a file of the add-on.

touches add-on files The fix replaces resources/assets/bin/procgov.exe inside the Hub's folder in the prefix. The original is kept in compatdata/2537590/flightsim-on-linux-backup/navigraph-hub/procgov.exe.orig, and this puts it back:

~/flightsim-on-linux/bin/flightsim-on-linux addon undo navigraph-hub

Get it

Navigraph publishes the Hub for Windows on its website. The installer used for this guide was an NSIS setup of about 97 MB.

Install it

Close the simulator and every program in its prefix, and run nothing else while the installer works. The ground rules explain why. Then give the installer to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install navigraph-hub ~/Downloads/"Navigraph Hub.exe"

The command refuses to start while the simulator runs or any program is open in the prefix, and names those programs. It then runs the installer in the simulator's prefix. On the test machine the installer needed no setting of its own.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply navigraph-hub

The Hub starts the 7-Zip it ships (7za.exe) through Process Governor, procgov.exe, to lower the priority of the extraction. Process Governor uses a Windows job-object call that Wine doesn't implement, so it fails with a Win32 error 1 and the extraction fails with it. The Hub's fallback then deletes the downloaded .7z and reports that the file isn't found. Without the fix, no AIRAC cycle and no plugin installs.

The fix is a small Windows program, built from the Go source in this repository, that takes the place of procgov.exe. It leaves out the priority part and passes the rest on:

  • A .7z archive goes to the 7-Zip of your own Linux system. The shim starts it through the /bin/sh of the simulator's container, with your system's dynamic loader and libraries: the container's own libraries are not the ones that 7-Zip was built for, and Wine can't run that loader directly, so a shell has to start it. Wine hands a Linux process back without a handle, so the shim reads the exit code from a file. A failed extraction comes back as exit code 2 with 7-Zip's message, which is how the Hub learns of it.
  • A .zip, a shell that doesn't start within five seconds, an exit status of 127 or a system without 7-Zip in a known place all go to the Hub's own 7za.exe. That is slower, but it works.

The shim looks for 7-Zip in these places under /usr, in this order, and runs it with the loader of that distribution: lib/7zip/7z (Arch, package 7zip), lib/p7zip/7z (Debian and Ubuntu), libexec/p7zip/7z (Fedora), bin/7z and bin/7zz. Only the first place was run on the test machine. The others are in the code and are expected to work, but nobody has tried them.

The shim is built on your machine, with Go, the first time apply or check needs it, and kept in ~/.cache/flightsim-on-linux/shims. Install go (Arch), golang-go (Debian, Ubuntu) or golang (Fedora) first.

What it saves, measured on the test machine, with 7-Zip running in Wine against the native one:

  • The AIRAC 2611 of the TFDi MD-11, 97,410 files in Nav-Primary, unpacked in 1.68 s on 31 October 2026, and about 12 s passed from the click to the end of the update. The cycle before it, 2610, took 27 minutes 31 seconds through Wine, by the Hub's log.
  • The time in Wine grows with the square of the number of files in a folder: 3,000 files took 2.25 s, 6,000 took 7.54 s and 12,000 took 27.94 s. What in Wine causes it was not measured.

The shim covers resources/assets/bin only. The copy in resources/app.asar.unpacked/dist/assets/bin/procgov.exe, 7.8 MB, is still the original, and the Hub worked that way on the test machine.

The unpacked MD-11 files were checked against each other: every terminal has its own file and the leg numbers have no gap. The simulator itself has not been seen loading an aircraft with the 2611 data yet.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut navigraph-hub

This writes an entry called "Navigraph Hub" in your application menu, with the Hub's own icon when 7z and magick are installed, and a "Close Navigraph Hub" action. The entry starts the Hub in the simulator's prefix with --disable-gpu-sandbox, the Electron option it needed to run on the test machine. With the simulator running it starts the Hub inside the simulator's container, and with the Hub already open it says so and does nothing. The action asks all of the Hub's processes to end, the way a polite kill does, and never uses kill -9.

Closing the Hub's window can leave it running in the prefix, and a program left open there holds the prefix. Use the menu action before you start the simulator or run an installer.

On a machine with several monitors, under XWayland, the Hub crashed at start on the test machine with X Error BadWindow / X_UnmapWindow, which has to do with that screen setup and not with the Hub. The test machine's answer, which is not part of apply, was to run only the Hub in a Wine virtual desktop. If you see the same crash, the setting is in the registry of the prefix: Desktop set to Default under HKCU\Software\Wine\AppDefaults\Navigraph Hub.exe\Explorer, and the size as Default under HKCU\Software\Wine\Explorer\Desktops, 1600x900 on the test machine. It doesn't touch the simulator, which runs in the same prefix.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check navigraph-hub

It prints two lines, each starting with ok or FAIL, and changes nothing, so you can run it with the simulator open:

  • procgov.exe is, byte for byte, the shim built from this repository;
  • a copy of the Hub's own procgov.exe is kept in the backup folder.

When the first one fails, the Hub has put its own file back, which it does when it updates. Run addon apply navigraph-hub again.

Known problems

  • A Hub update restores procgov.exe, and the next AIRAC or plugin install fails again until you apply the fix. apply keeps the new original as the backup and leaves an older build of the shim alone.
  • The Hub's config.json keeps your Navigraph tokens in plain text. Don't paste it into an issue, a forum post or an AI chat.
  • Right after an update the MD-11's button stayed on INSTALL with the disk already at the new cycle, and went back to REMOVE only when the Hub was closed and opened again. Switching tabs didn't redo the detection. The shim isn't part of the Hub's state, which it reads from cycle.json.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo navigraph-hub
~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut navigraph-hub --remove

The first puts the Hub's own procgov.exe back and deletes the copy. If the Hub updated since the fix, procgov.exe is already the new Hub's own and is not the stand-in any more: undo then leaves it as it is, drops the older copy and says so. The second takes out the menu entry.
