Glass Cockpit DLSS Fix

Tested with Glass Cockpit DLSS Fix 1.0.2 on 20 October 2026. It takes the DLSS blur off the glass cockpit screens. It needs ReShade, a Proton FS2024 built with two vkd3d-proton patches, and two lines in its ini file.

touches add-on files apply edits the add-on's own ini file, glass-cockpit-dlss-fix.ini in the simulator's folder, or creates it. The first time, it keeps the original (or notes that there was none) in compatdata/2537590/flightsim-on-linux-backup/glass-cockpit-dlss-fix, and this puts it back:

~/flightsim-on-linux/bin/flightsim-on-linux addon undo glass-cockpit-dlss-fix

Get it

It is a free ReShade add-on, from the project's releases page on GitHub. The file is glass-cockpit-dlss-fix.addon64 of release 1.0.2. You don't need to download it yourself: the install command does.

Install it

Install ReShade first. The simulator has to be closed.

~/flightsim-on-linux/bin/flightsim-on-linux addon install glass-cockpit-dlss-fix

The command downloads https://github.com/IFreemz/msfs2024-glass-cockpit-dlss-fix/releases/download/v1.0.2/glass-cockpit-dlss-fix.addon64 with curl (the release is tagged v1.0.2), checks that its sha256 is 9474b66e2e22bc005233463574fc9ba9c107d4bfa8364e5c3478588f0e8f2036, keeps it in ~/.cache/flightsim-on-linux/downloads and copies it into the simulator's folder, beside ReShade's dxgi.dll. A file with another hash is thrown away and nothing is installed. The hash is pinned because this is the release the fix was measured with. A newer release needs a newer test.

If you already downloaded the file, give it to the command: addon install glass-cockpit-dlss-fix /path/to/glass-cockpit-dlss-fix.addon64. It must be the same release.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply glass-cockpit-dlss-fix

The add-on only redraws a cockpit screen when the root signature active at the draw is the very same object that the screen's pipeline was created with, a pointer comparison. Two things in vkd3d-proton, the Direct3D 12 layer of Proton, stopped that from working, and Proton FS2024 carries a patch for each.

  • root-signature-reuse-identical-blob.patch. On Windows, creating the same root signature twice returns the same object. vkd3d-proton makes a new object every time. The simulator makes the same root signature many times: 95 created in a session with the PMDG 777, 73 of them with the content of another one still alive, and 13 live copies of the screens' root signature. In 10 seconds in the cockpit, 272,765 draws used the very object and 3,272,991 used another copy with identical content. With the stock Proton, the add-on refused 6,894 of 6,894 screen draws with skip reason=root_layout. The patch makes CreateRootSignature return the live object when the blob is identical byte for byte, only while its public reference count is above zero. With it, the same 95 creations gave 73 returns of the live object, no duplicate, and no refusal for root_layout.
  • descriptor-heap-covers-its-cpu-handles.patch. After the first patch the add-on refused the screens with texture_not_recognised. On NVIDIA it recognises a screen's texture by the 32 bytes of its descriptor, which on the Windows driver depend only on the resource and the view. vkd3d-proton doesn't fill them the same way. On AMD and Intel the add-on follows each descriptor through the copies that the game makes, and an ini option turns that on for NVIDIA as well (below). With it, the log showed screen texture found through descriptor tracking and fix is active. The statistics line still had 5,339 draws of 154,228 refused as descriptor_unreadable and one screen flickered a little, because vkd3d-proton handed out descriptor addresses beyond the heap's allocation. This patch fixes that.

apply writes two lines in glass-cockpit-dlss-fix.ini and keeps every other line, with the file's line endings:

  • dark_screen_fix=1 under [experimental].
  • descriptor_tracking=1 under [debug], only when the GPU the simulator uses is NVIDIA. The command asks vulkaninfo: with one GPU it is that one, and with several it is the discrete one, the way the other tools of this repository choose. When it can't tell, because vulkaninfo is missing or two discrete GPUs are present, it leaves the option alone and says so. Install vulkan-tools, or set the option by hand.

If the ini file doesn't exist, apply creates it with only those two sections.

Start it

There is nothing to start. The add-on loads through ReShade with the simulator. Its settings window opens with Ctrl+Shift+F6, the default in the ini's [hotkeys] section.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check glass-cockpit-dlss-fix

It prints seven lines, on NVIDIA and elsewhere, each starting with ok or FAIL, and changes nothing:

  • ReShade's dxgi.dll and the .addon64 are in the simulator's folder;
  • dark_screen_fix=1 is set;
  • on NVIDIA descriptor_tracking=1 is set, and elsewhere the line says it isn't needed;
  • the Proton's fs2024-build.txt lists both vkd3d-proton patches of this repository, and the d3d12core.dll in it is the one the build recorded.

When the Proton lines fail, rebuild Proton FS2024 with bin/flightsim-on-linux proton build.

Known problems

  • At a strong reflection angle a screen goes back to DLSS.
  • Lit button legends stay out of the fix.
  • With DLSS 5 Neural Rendering, that add-on has to run after this one. Its guide says how.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo glass-cockpit-dlss-fix

This restores the ini file as it was before the first apply, or deletes it if apply had created it. The add-on stays. To remove it, delete glass-cockpit-dlss-fix.addon64 from the simulator's folder, and its ini, log and status files if you want them gone.
