Orbx Central

Tested with Orbx Central 4.5.50, the Windows build, on 16 October 2026. Use the Windows build in the simulator's prefix and not the Linux AppImage. Open it only with the simulator closed. Nothing in the prefix changes.

Get it

Orbx publishes Orbx Central for Windows and for Linux. Take the Windows installer, orbx-central-4.5.50.exe here, about 738 KB, built with electron-builder. Where it is downloaded from isn't recorded here; get it from Orbx.

The Linux AppImage runs, and on 16 October 2026 it showed only the Channel Islands. Its product list keeps a product only when the product is marked for Linux (operatingSystems.linux), whether you bought it or not. In the cache of that day, 245 of 2,372 products were marked for Linux. Two sound sets from Boris Audio Works for the PMDG 737NG and the B777 that the account owns (owned: true in the same cache) were marked for Windows only, so the AppImage hid them. The Windows build showed both and installed them. The catalogue changes, so these numbers will too: the operatingSystems of each product is in AppData/Roaming/Orbx/Central/Persistence/product.cache.json in the prefix.

Install it

Close the simulator and every program in its prefix, and run nothing else while the installer works. The ground rules explain why. Then give the installer to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install orbx-central ~/Downloads/orbx-central-4.5.50.exe

The command refuses to start while the simulator runs or any program is open in the prefix, and names those programs. It runs the installer in the simulator's prefix with powershell.exe turned off. An electron-builder installer calls PowerShell, and Wine's powershell.exe exits with code 0 without doing anything. Without the override, this installer stopped on a message that Orbx Central was running (the message was in Portuguese on the test machine) with nothing running. With powershell.exe off, it installed without asking.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply orbx-central

This changes nothing in the prefix, and then runs the check. The launch script starts Orbx Central with --disable-gpu-sandbox, the Electron option that let it run on the test machine, and only when the simulator is closed.

The reason for the second part: an open Orbx Central holds the prefix's wineserver. Steam then waits on it and does not start the simulator. On 16 October 2026 the simulator started five seconds after Orbx Central closed. So the menu entry refuses while the simulator runs, and you close Orbx Central, with its menu action, before you start the simulator.

Orbx's Chromium draws on the GPU and takes video memory that the simulator then lacks: the GPU process of the Windows build held 295 MiB with no option, and the native one 485 MiB. On the test machine --use-gl=angle --use-angle=swiftshader, which draws on the CPU, drew normally and cut the Windows build to 64 MiB. That helps on a card whose memory the simulator needs and is not part of the script. If you want it, pass the options after the script name: addon launch orbx-central launch -- --use-gl=angle --use-angle=swiftshader. Two other ways failed: --disable-gpu did not open the native build, and selecting the integrated Radeon card for the Windows build gave a black window.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut orbx-central

This writes an entry called "Orbx Central" in your application menu, with its own icon when 7z and magick are installed, and a "Close Orbx Central" action. With Orbx Central already open the entry says so and does nothing. The action asks Orbx Central and its saturn-win helper processes to end, the way a polite kill does, and never uses kill -9.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check orbx-central

It prints one line, starting with ok or FAIL, and changes nothing, so you can run it with the simulator open: the Windows build of Orbx Central is installed in the prefix.

Known problems

  • Open, it keeps the simulator from starting through Steam. Close it first.
  • The native build hides products that Orbx hasn't marked for Linux.

Undo

addon undo orbx-central has nothing to restore, because apply changed nothing. Take out the menu entry with:

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut orbx-central --remove
