ReShade

Tested with ReShade 6.8.0 (build 6.8.0.2155) on 14 October 2026. To make it load, copy three files into the simulator's folder and change one line of one of them.

ReShade is a third-party program. This guide only gets it to load in the simulator. Your shaders stay yours: it copies, edits and fixes none of them.

Get it

ReShade is free and comes from reshade.me. It has no installer for Linux. The files on the test machine were copied from a Windows install of ReShade, and nobody tried its installer under Wine. Install ReShade for the simulator's FlightSimulator2024.exe on a Windows PC, or in any Windows folder you have, and take the folder it makes.

You need three files from that folder: dxgi.dll, ReShade.ini and ReShadePreset.ini.

Install it

Close the simulator first. The CLI takes a file, so give it the dxgi.dll of the Windows install, and it reads the other two beside it:

~/flightsim-on-linux/bin/flightsim-on-linux addon install reshade /path/to/windows-reshade-folder/dxgi.dll

The command refuses to start while the simulator runs or any program is open in the prefix, and names those programs. Then it copies into the simulator's install folder, next to FlightSimulator2024.exe:

  • dxgi.dll. If the folder already has a different dxgi.dll, the install stops and leaves it alone: move it away yourself first. The same file is fine.
  • ReShade.ini, with one line rewritten: IntermediateCachePath in a Windows install names a folder of that Windows user, and here it becomes C:\users\steamuser\AppData\Local\Temp\ReShade, inside the prefix. A ReShade.ini that was already in the folder is kept in compatdata/2537590/flightsim-on-linux-backup/reshade first, as ReShade.ini.previous. Installing again never replaces that copy.
  • ReShadePreset.ini. A preset that is already there stays, because ReShade saves its own there when Auto Save is on.

Nothing else is touched. No shaders are copied, not even the reshade-shaders folder of the Windows install. Put your own shader and texture folders in the simulator's folder, where your ReShade.ini expects them.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply reshade

This changes nothing, and then runs the check. There is no launch option, and this is why. Proton puts dxgi=n into the simulator's environment. With that, Wine takes the dxgi.dll from the game's folder before its own, which is DXVK's, and ReShade passes the calls on to it. So you don't need WINEDLLOVERRIDES=dxgi=n,b in the Steam launch options. A dxgi.dll in that folder only counts for programs whose executable is in that folder.

The proof on the test machine: ReShade.log says it was loaded from S:\steamapps\common\MSFS2024\dxgi.dll, with no launch option set for it.

Start it

There is nothing to start. ReShade loads with the simulator, and you open its overlay in the simulator as on Windows.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check reshade

It prints two lines, each starting with ok or FAIL, and a third one once the simulator has run, and it changes nothing:

  • dxgi.dll in the simulator's folder is ReShade's;
  • IntermediateCachePath in ReShade.ini is the folder inside the prefix (or the line is absent);
  • once ReShade.log exists, it records ReShade loading.

Known problems

  • Some effects fail to compile under Wine. Wine's shader compiler, d3dcompiler_47, refuses isnan in a pixel shader with Function "isnan" is not defined, the same effect compiles on Windows, and it is the effect's code that has to change. This guide doesn't edit any.
  • In ReShade.log, read the first error. The ones after an E5017 about fastopt are consequences of it.
  • ReShade doesn't refresh its cached .i files when you edit a file that an effect includes. Delete the cache folder inside the prefix (drive_c/users/steamuser/AppData/Local/Temp/ReShade) to force it.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo reshade

This moves dxgi.dll, ReShade.ini and ReShadePreset.ini out of the simulator's folder into compatdata/2537590/flightsim-on-linux-backup/reshade/removed, so the preset you tuned isn't lost. Each file gets the date and time of the undo in its name, so an earlier undo's copies are never overwritten. If the simulator's folder had a ReShade.ini before the install, that one goes back where it was. Close the simulator first. Your shader and texture folders stay where they are.
