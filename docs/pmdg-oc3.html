PMDG Operations Center 3

Tested with PMDG Operations Center 3 (OC3) 3.0.289 on 13 October 2026. It takes one registry value, two options on OC3's command line, and an update that has to come from outside the app. No Proton FS2024 patch is involved. On the test machine OC3 installed the 737-800 (4.0.63) and the 777 (2.4.147), and no fix of the aircraft themselves was needed.

Get it

OC3 is the PMDG client that installs and updates the PMDG aircraft. PMDG publishes the current installer on its own download server, and a public manifest at https://cdn.pmdg.com/oc3-client-releases/prod.yml names the file and its SHA-512 hash. You don't have to find the file yourself: the update command below reads that manifest and downloads the installer. The sources don't say what the aircraft cost, so check PMDG's store page for that.

Install it

Close the simulator and every other program of its prefix first, and run nothing else while the installer works. The ground rules explain why. Then:

~/flightsim-on-linux/bin/flightsim-on-linux addon launch pmdg-oc3 update

This does four things, in this order:

  • It reads PMDG's manifest and downloads the installer it names into the cache folder, unless that file is already there.
  • It computes the SHA-512 of the file and compares it with the manifest. If they differ, it deletes the file and stops. If they match, it says so. The hash shows that the file is the one PMDG published. It does not replace the signature check that OC3 would do on Windows.
  • It hands the file to addon install pmdg-oc3, which refuses to start while the simulator runs or any program is open in the prefix, and names those programs.
  • It runs the installer in the simulator's prefix with powershell.exe turned off for that one program.

To download and check the file without installing it, add --download-only: the command then prints where the file is. If you already have an installer, give it to the CLI yourself:

~/flightsim-on-linux/bin/flightsim-on-linux addon install pmdg-oc3 ~/Downloads/oc3_setup_3.0.289.exe

The PowerShell override is there for this reason. The powershell.exe in a Wine prefix is a stand-in: it accepts any command line, prints nothing and exits with 0. The OC3 installer asks PowerShell whether OC3 is running, and the stand-in's 0 means yes. With OC3 closed, the installer still stops. On the test machine its message was Não é possível fechar o PMDG OC3, which is Portuguese for "can't close PMDG OC3". With powershell.exe off, the first question fails and the installer falls back to tasklist | find, which Wine implements.

The same reason makes OC3's own update fail. OC3 downloads the new version up to 100% and then shows Update download error: SyntaxError: Unexpected end of JSON input. Its updater checks the installer's signature by calling PowerShell and reading the answer as JSON, and the stand-in's answer is empty. A fake PowerShell that always answered "signature valid" was rejected on purpose, because it would switch off a real security check for good. Update with the command above instead.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply pmdg-oc3

This sets one value for PMDG OC3.exe only, Decorated to N, in the X11 driver's section of the prefix registry (HKCU\Software\Wine\AppDefaults\PMDG OC3.exe\X11 Driver), and then runs the check. OC3 draws its own title bar. By default Wine asks the window manager for a frame as well, and the KDE title bar then sits on top of OC3's. With Decorated=N only OC3's bar is left, and Wine draws the resize border. On the test machine this was measured against two other arrangements, by screenshots: a KWin rule that hides the title bar and borders cut OC3's own bar at the top, so it was dropped. apply keeps what was there before in compatdata/2537590/flightsim-on-linux-backup/pmdg-oc3. The key belongs to the X11 driver, and OC3 was measured with the simulator closed, where Proton uses that driver unless you turned the Wayland driver on (see the ground rules). Whether the Wayland driver reads the key was not measured.

OC3 also needs two options on its command line, and the menu entry and the launch script always add them:

  • --disable-gpu-sandbox. Without it OC3 closes about a second after it opens. The log shows GPU process launch failed: error_code=43 nine times, then GPU process isn't usable. Goodbye. Chromium starts a child process for the GPU inside its sandbox, and Wine can't create that process the way Chromium asks. Only the GPU process loses its isolation; the rest of the sandbox stays.
  • --disable-gpu. With acceleration on, OC3 drew its content one menu row below where the clicks landed, with a black strip under the title bar. On screen that looks like the pointer on one item and the highlight on the item below it.

The Wine virtual desktop for OC3 alone was tried and changed neither the black strip nor the pointer.

Option: dark window colours

This is cosmetic, and it is not part of apply. Without the KDE frame, the border that Wine draws uses colours from the prefix, and by default they are light. The wide resize border uses ActiveBorder and InactiveBorder. The two thin relief lines outside it use ButtonHilight, ButtonLight, ButtonShadow and ButtonDkShadow. Setting all six to 18 18 18, the colour of OC3's background, gives the border the colour of OC3's background. The colours belong to the whole prefix, not to OC3, and every program in it that draws classic buttons and dialogs uses them. Set them only if the light border bothers you more than a change in how those programs look. With OC3 and the simulator closed:

protontricks -c 'wine reg add "HKCU\Control Panel\Colors" /v ActiveBorder /t REG_SZ /d "18 18 18" /f' 2537590
protontricks -c 'wine reg add "HKCU\Control Panel\Colors" /v InactiveBorder /t REG_SZ /d "18 18 18" /f' 2537590
protontricks -c 'wine reg add "HKCU\Control Panel\Colors" /v ButtonHilight /t REG_SZ /d "18 18 18" /f' 2537590
protontricks -c 'wine reg add "HKCU\Control Panel\Colors" /v ButtonLight /t REG_SZ /d "18 18 18" /f' 2537590
protontricks -c 'wine reg add "HKCU\Control Panel\Colors" /v ButtonShadow /t REG_SZ /d "18 18 18" /f' 2537590
protontricks -c 'wine reg add "HKCU\Control Panel\Colors" /v ButtonDkShadow /t REG_SZ /d "18 18 18" /f' 2537590

A program that is already open keeps the old colours, so close it and open it again. These were the values on the test machine before: 255 255 255 for ActiveBorder, InactiveBorder and ButtonHilight, 227 227 227 for ButtonLight, 166 166 166 for ButtonShadow and 106 106 106 for ButtonDkShadow. Run the same commands with those values to go back. A light line of one pixel stays around the window either way. It uses ButtonFace, the background of every classic button and dialog in the prefix, whose text is black, so darkening it would need a dark theme for the whole prefix. That was left alone.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut pmdg-oc3

This writes an entry called "PMDG OC3" in your application menu, with OC3's own icon when 7z and magick are installed. It starts OC3 with both options. With the simulator closed it starts OC3 in the simulator's prefix. With the simulator running it starts OC3 inside the simulator's container, as the ground rules describe. With OC3 already open it says so and does nothing. The output of OC3 goes to a log file in the cache folder. Updates and installs still need the simulator and everything else closed. OC3 has no background service: you open it when you want it.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check pmdg-oc3

It prints one line, starting with ok or FAIL, and changes nothing: it reads user.reg in the prefix and wants Decorated to be N for PMDG OC3.exe. When it fails, run apply. The two Electron options can't be checked from outside; the menu entry and the launch script carry them.

Known problems

  • A light line of one pixel stays around the window, as above.
  • OC3's own update fails, as above. Use the update command.
  • If OC3 closes about a second after it starts, it was started without --disable-gpu-sandbox. Start it from the menu entry or from the launch script.
  • No fix of the PMDG aircraft themselves is recorded. The 737-800 and the 777 that OC3 installed on the test machine needed none.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo pmdg-oc3
~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut pmdg-oc3 --remove

The first command puts Decorated back to what it was, or removes it when apply added it. A value that was already N before apply, because you set it, stays. The second command takes out the menu entry. The colours have their own commands, above.
