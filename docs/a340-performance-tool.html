A340 Performance Tool

This does natively what the A340 Performance Tool 1.1.0 does on Windows. The Windows tool was not installed; the read-only behaviour it relies on was checked in a throwaway prefix on 28 October 2026. It is three commands and a small background loop, and it is optional: the effect on stutters was not measured, and the author doesn't promise one. touches add-on files

The tool changes the permissions of one file, ToLissPrevLog.txt in the A340-600's WASM work folder. It makes the file read-only before a flight and gives it back its earlier permissions when the simulator closes. The earlier permissions and the state of the tool are kept in compatdata/2537590/flightsim-on-linux-backup/a340-performance-tool. addon undo a340-performance-tool gives the file back its permissions at any time the simulator is closed.

Get it

There is nothing to download. The Windows tool, A340_Performance_Tool_V.1.1.0_mFV6R.zip on the test machine, is a community tool, and this guide doesn't have its page. Its window is a Windows Forms program written in Windows PowerShell 5.1, which a Wine prefix doesn't have. All the tool does is switch the read-only attribute of that one file on and off, and Wine treats a file as read-only when Linux has taken away its write permission. So this add-on does the same job natively, without Wine. It needs the Aerosoft A340-600 Professional and one flight with it, because the file exists only after the first flight.

Install it

Nothing to install. addon install a340-performance-tool says it has nothing to install.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply a340-performance-tool

This changes nothing, says how to turn the tool on, and runs the check. The tool works one flight at a time, so you turn it on before each flight. In Wine, "read-only" is the lack of write permission: on 28 October 2026, in a throwaway prefix with Proton FS2024, attrib +R took the write permission away, and a chmod a-w from Linux showed up in Wine as read-only. With the file in that state Wine refused to append to it, delete it or replace it, as Windows does.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut a340-performance-tool

This writes an entry called "A340 Performance Tool" in your application menu. It runs on, and tells you the result in a desktop notice. You can run the three commands from a terminal as well:

~/flightsim-on-linux/bin/flightsim-on-linux addon launch a340-performance-tool on
~/flightsim-on-linux/bin/flightsim-on-linux addon launch a340-performance-tool state
~/flightsim-on-linux/bin/flightsim-on-linux addon launch a340-performance-tool off

Turn it on with the simulator closed, then start the simulator. on does this:

  • It refuses while the simulator is open.
  • It refuses when the A340's work folder is missing or is a link, when ToLissPrevLog.txt doesn't exist yet (fly the A340 once first), or when ToLissPrevLog.txt or ToLissLog.txt is already read-only or a link.
  • It notes the file's permissions, makes it read-only, and starts a small background loop of its own. This is not the addon watcher service: it lives for one flight.
  • If the loop doesn't start, it gives the permissions back and says so.

The loop looks for the simulator every 3 seconds. After the simulator has run and closed, which it sees as two looks in a row without it, the loop gives the file its earlier permissions and ends. If the simulator doesn't open within 3 hours, it gives them back anyway. off does it by hand, and refuses while the simulator is open. state says whether the tool is on, since when, whether the loop is running, the file's permissions and the last event. A tool that is already on says so and does nothing. A tool left on by a loop that died is recovered by the next on.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check a340-performance-tool

It prints two lines, each starting with ok or FAIL, and changes nothing:

  • the A340's work folder is a real folder and ToLissPrevLog.txt is a real file;
  • when the tool is off, the file is writable; when it is on, the file is read-only and the loop is waiting for the simulator.

It fails when a session is on but the file is writable or the loop is gone, and when the file is read-only with no session of this tool behind it. The check passes when the tool is off, because that is a normal state. Close the simulator and run off to clear a failure.

Known problems

  • The effect on stutters was not measured on Linux, and the author of the Windows tool doesn't promise one.
  • The file only exists after a first flight, so the first time you have nothing to protect.
  • If something kills the loop during a flight, the file stays read-only until you run off with the simulator closed. The check says so.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo a340-performance-tool
~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut a340-performance-tool --remove

The first command is off, with the simulator closed: it gives ToLissPrevLog.txt the permissions it had before. The second takes out the menu entry.
