Proton Fenix A320

A Proton-CachyOS release with 13 Wine modules rebuilt: eleven from the fenix-a320-linux-patch overlay and two fixes from this project. It runs the simulator and every other add-on in the prefix, so the fixes reach all of them.

Why the simulator needs a special Proton

Most add-on problems can be fixed inside the prefix. A few are bugs in Wine itself, and those need a rebuilt Wine:

ModuleWhat goes wrong without itSource
11 modules, among them ntdll, kernelbase, crypt32, d2d1, dwriteThe Fenix runner spins at full CPU without opening a window, the aircraft won't power up, and the Fenix displays draw wrong.fenix-a320-linux-patch v0.1.0-preview.7, by its own authors
gdiplusFSLabs displays are covered in glow, and the MCDU and clock letters lose their right side.this project
shell32Programs built on H.NotifyIcon, such as AutoFPS with "Close to Tray", crash on start.this project

The Proton also carries a user_settings.py with the nine settings the overlay's installer writes, plus cef_browser.exe in WINE_TRACK_WRITECOPY. Without that last one the FSLabs EFB browser crashes when it starts.

How it is built

bin/flightsim-on-linux proton build runs proton/build-proton-fenix.sh, which:

  1. downloads the Proton-CachyOS release and checks it against the release's own sha512;
  2. downloads the overlay patch from the overlay's tagged source and checks a pinned sha256;
  3. asks GitHub which wine-cachyos commit the release was built from, and fetches only that commit;
  4. applies the three patches and stops at the first one that doesn't apply cleanly;
  5. refuses to continue if the wineserver protocol changed, because the release's 32-bit parts would stop talking to it;
  6. compiles the 13 modules, checks that none needs a system library the original didn't, and swaps them into a copy of the release;
  7. starts a Windows process inside the Steam Linux Runtime the release asks for;
  8. only then moves the result into compatibilitytools.d, under a new name. It never overwrites an existing folder.

The built Proton has a fenix-rebuild.txt listing the release hash, the Wine commit and a hash for every patch and module, so you can tell exactly what you are running.

Only cachyos-11.0-20261005-slr has been verified. You can pass another cachyos-11 release, proton build cachyos-11.0-…, and the script stops if a patch no longer applies. The overlay's authors publish a new variant when CachyOS moves to a Wine the patch doesn't fit.

How it is checked

bin/flightsim-on-linux proton check creates a throwaway prefix, compiles four small Windows programs and runs them with the Proton the simulator uses:

CheckPasses when
Overlay loaderA program named Fenix.exe sees KERNEL32.DLL and KERNELBASE.dll spelled as on Windows. The probe is the overlay's own loader-case-probe.c.
Tray icon by GUIDA tray icon can be changed and removed by its GUID alone. Needs an X11 display; without one the check says it could not run.
GDI+ path gradientFocus, blend and preset colours land where Windows puts them.
GDI+ centred textAn "M" centred on x = 100 is centred within 1.5 pixels. Stock Wine draws it about 4 pixels to the right.

Run against stock Proton-CachyOS, all four fail. Built without the shell32 patch, only the tray check fails. That is how we know each check catches what it claims to.

What has not been measured

The Proton this script builds passes the four checks and starts the Fenix runner. Flights so far used a Proton put together by hand from the same release and the same patches. A full flight with the scripted build hasn't been logged yet.

Undo

Pick another Proton under Compatibility in the simulator's Properties, then delete the Proton-Fenix-A320-… folder from ~/.local/share/Steam/compatibilitytools.d/. The build cache lives in ~/.cache/flightsim-on-linux and can go too.
