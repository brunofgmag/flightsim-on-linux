MSFS 2024 GPU memory warning

Tested with simulator 1.9.21.0 on 29 October 2026. One command, run with the simulator closed. touches add-on files: it edits two files of the simulator's own fs-base-ui package, and ~/flightsim-on-linux/bin/flightsim-on-linux addon undo simulator-gpu-memory-warning puts the originals back.

What the warning is

The simulator shows a notification, "Resource usage exceeds GPU memory capacity, lower graphics settings for better performance", when its video memory use goes past the budget it planned for. The simulator offers no setting for it, and a Community package can't replace the page that shows it.

The warning is only a symptom. Hiding it doesn't give the simulator more memory and doesn't change what it does when it passes the budget. On 29 October 2026, on the test machine, the warning came with a jump in the simulator's own RAM:

  • With a 1,870 MiB reserve in the launch options (see Proton FS2024) and the FSLabs A321 loaded, the warning reached the simulator's notification manager at 10:36:08. Between 10:36:39 and 10:37:39 the simulator's RAM and swap together grew by 26.2 GB, then by 5.4, 2.0, 1.2 and 0.7 GB in the next minutes. The simulator was closed at 10:44 with 6.1 GB of RAM free.
  • In a third session that day, with the reserve taken out and the same aircraft, the video memory filled up without passing the budget. No warning came, and RAM and swap stayed at 20.0 to 20.2 GB for the 20 minutes until the simulator was closed.

So the warning marks the moment the simulator passed its budget. The test machine's measurements point at the reserve as what pushes it past, and the cause of the RAM jump hasn't been proven. If you see the warning, look at the simulator's memory before you flick it away.

Make it run

Close the simulator, then:

~/flightsim-on-linux/bin/flightsim-on-linux addon apply simulator-gpu-memory-warning

It does three things, then runs the check:

  1. It adds a small script to Packages/fs-base-ui/html_ui/Global/notifications.html in the simulator's install folder, right after the line that loads the page's bundle. The script waits for the page's NotificationsManager and wraps the three methods that show or update a notification. A notification is dropped when it carries the key NOTIF_LOW_GPU_MEMORY_CAPACITY or the warning's text. The texts are read from the simulator's own language files (fs-base/*.locPak), so each language the simulator ships is covered. Every other notification shows as before.
  2. It corrects the size of that page in the package's layout.json, so the file list still describes the files on disk.
  3. It deletes the Community package flightsim-on-linux-gpu-memory-warning if an earlier version of this fix put it there. The simulator mounts Community packages too late for this page.

Before it changes anything it keeps both originals in compatdata/2537590/flightsim-on-linux-backup/simulator-gpu-memory-warning. Running apply again is safe: it starts from the saved original and rebuilds the page. If the page already carries the filter and the saved original is gone, it stops and says so rather than guess.

On 29 October 2026 the simulator loaded the filter on its own, and a copy of the warning sent to its notifications never reached the screen. The real warning has not been seen to stay hidden in flight.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check simulator-gpu-memory-warning

It changes nothing, so you can run it with the simulator open. Each line starts with ok or FAIL:

  • the saved original of notifications.html is there (without it the check stops at one FAIL and says to run apply);
  • the page on disk is the saved original plus the filter, rebuilt from your current language files;
  • layout.json gives the page's size on disk;
  • the old Community package is not there. This line appears only when it is, as a FAIL.

Known problems

  • A simulator update puts the original page back. The check then fails on the first or second line. Run apply again, with the simulator closed.
  • If a simulator update changes the page so that the line loading the bundle is no longer there exactly once, apply stops with a FAIL and changes nothing. The fix then needs updating for that simulator version.
  • The filter hides one notification. It does nothing about the memory behind it.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo simulator-gpu-memory-warning

Close the simulator first. It puts the saved notifications.html and the page's original size back, deletes the old Community package if it is still there, and then deletes the backup folder. If the page doesn't carry the filter, for example after a simulator update, it leaves the page alone.
