FlyByWire Installer

Tested with FlyByWire Installer 3.7.2 on 14 October 2026. It is a native Linux program, so it doesn't go into the simulator's prefix. It has one trap: if you give it only the simulator's base folder, it writes the same path as the Community folder and as the install folder.

Get it

FlyByWire Simulations publishes the installer as an AppImage for Linux, 122 MB for this version. On the test machine its SHA-512 was checked against the latest-linux.yml of the FlyByWire CDN. Where it is downloaded from and what it costs aren't recorded here; get it from FlyByWire.

~/flightsim-on-linux/bin/flightsim-on-linux addon install flybywire-installer

This prints where to get it and what kind of program it is. It installs nothing.

Install it

Make the AppImage executable and run it with these options. With them it drew its window and stayed out of nvidia-smi on the test machine:

chmod +x FlyByWire-Installer-3.7.2-x86_64.AppImage
./FlyByWire-Installer-3.7.2-x86_64.AppImage --no-sandbox --disable-gpu

It doesn't find the simulator by itself and asks for the "MSFS 2024 base path". Give it the folder that holds UserCfg.opt, which the CLI prints as base:

~/flightsim-on-linux/bin/flightsim-on-linux machine

The trap

With only the base path, the installer saved that same path as the Community folder and as the folder to install into, in ~/.config/FlyByWire Installer/config.json. On 14 October 2026 the FSLTL Traffic Base Models 1.6.1 (49 GB) were installed to fsltl-traffic-base in the base folder, outside Packages/Community, where the simulator doesn't look.

So set the Community folder in the installer's settings to the simulator's Community folder, which the CLI prints as community, before you install anything. The test machine moved the package that had landed in the base folder into Community, and after that the installer showed the Base Models as installed, so later updates go to the right place. Reinstalling the installer, or changing the folders in its settings, can bring the problem back, so check again then.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply flybywire-installer

This changes nothing. It reads two settings of the MSFS 2024 block of ~/.config/FlyByWire Installer/config.json, communityPath and installPath, follows links and compares both with the simulator's Community folder. It prints those two paths and nothing else from the file, which can hold data of your account.

Start it

There is no menu entry, because the AppImage can be anywhere on your disk. To make one, point a .desktop file at your copy with the same two options.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check flybywire-installer

It prints two lines, each starting with ok or FAIL, and changes nothing, so you can run it with the simulator open: communityPath is the simulator's Community folder, and installPath is too. A failing line names the path it found and the one it wants.

Known problems

  • It doesn't find the simulator on its own.
  • Giving it only the base folder sends the downloads outside Community, as above.

Undo

addon undo flybywire-installer has nothing to restore, because apply changed nothing.
