Launch options

The launch options of the simulator are a line of settings that Steam puts in front of the game. This page says what each option does, where the reason comes from, and which machines need it. It separates what a problem calls for, what suits a kind of machine and what is only a choice. Measurements are from one machine: an RTX 4080 with an AMD iGPU and a Ryzen 9 9950X3D, on KDE Plasma under Wayland, in October and November 2026.

Where they go

In Steam, right-click Microsoft Flight Simulator 2024, choose Properties and use the Launch Options box. The line has three parts, in this order: settings written as NAME=value, then the word %command%, which Steam replaces with the game's own command, then any arguments for the game. Everything before %command% is an environment variable for the game. A program that goes before %command%, such as game below, runs the game for you.

Steam keeps the line in localconfig.vdf and rewrites that file when it closes, so nothing in this project edits it. bin/flightsim-on-linux machine --json prints the line you have now, in launch_options, and bin/flightsim-on-linux doctor reads it too.

Proton FS2024 is not an option in this line. You pick it in the Compatibility tab, as Start here says.

Needed by everyone

Nothing. No option below is needed on every machine, and the setup in Start here sets none. Each one answers a problem or suits a kind of machine, and the next sections say which.

When you see the problem

PROTON_NO_NTSYNC=1

Proton uses ntsync, a Linux kernel driver for Windows-style synchronization, whenever the kernel has /dev/ntsync. With plain Proton-CachyOS in July 2026, the test machine froze in the main menu or while loading an aircraft, and turning ntsync off fixed it. Add this option if your simulator freezes there. PROTON_USE_NTSYNC=0 looks like it does the same, but Proton ignores it. The ground rules have the whole story, and doctor says whether ntsync is on.

WAYLANDDRV_FOCUS_LOSS=0

When the simulator window loses focus, the simulator turns its frame generation off and shows only the frames it renders itself. Under Wine's Wayland driver, this option keeps the simulator as the foreground window when another window takes the focus. On 3 November 2026, with DLSS frame generation on, the simulator dropped to its rendered frame rate as soon as another window took the focus, and with the option set frame generation stayed on. It does nothing under the X11 driver. The Proton FS2024 page says what still takes the foreground away.

STEAM_COMPAT_LIBRARY_PATHS=/path/to/your/steam/library

Only the ChasePlane bridge needs it. Without it, Proton maps drive S: to the steamapps folder itself, the simulator's path has no steamapps\common in it, and the bridge doesn't recognise the installation. The value is the Steam library that holds the simulator, the folder with steamapps inside. bin/flightsim-on-linux machine --json prints it as sim_library. The ChasePlane guide has the rest.

By machine

An NVIDIA GPU

PROTON_DLSS_UPGRADE=1 makes Proton download the newest DLSS from its own manifest and put it in the prefix. The upgraded frame generation file, nvngx_dlssg.dll 310.9.16, goes to system32/umu. It is also one of the three options the MFG Unlocker check looks for.

A second option, DXVK_NVAPI_DRS_SETTINGS, picks the DLSS Super Resolution preset. It is in the preferences below.

An HDR monitor

PROTON_ENABLE_HDR=1 asks Proton for HDR. Use it only with an HDR monitor, and with the Wayland driver below: KWin doesn't manage colour for XWayland windows, so under the X11 driver the desktop gives the simulator no HDR. The simulator reads the screen once, when it starts, and after a start on the wrong monitor its HDR10 option stayed locked. Start it on the screen you play on. The NVIDIA driver matters too. On 25 October 2026 the driver 580.178.04 offered no HDR on its Wayland surface, so the simulator started in SDR and the option did nothing, and 615.78.08 offers HDR10 and scRGB there.

A Wayland session

PROTON_ENABLE_WAYLAND=1 makes Wine draw the simulator's windows with its Wayland driver. Without it Proton uses the X11 driver, which runs through XWayland. HDR needs the Wayland driver. The price is the tray: under the Wayland driver, the tray icons of GSX, ChasePlane and Volanta show up in a small window of Wine's own explorer.exe and not in the KDE tray. The ground rules explain both drivers. With the Wayland driver, WAYLANDDRV_FOCUS_LOSS=0 above also applies.

Two GPUs, or an X3D CPU with two chiplets

On a machine with an integrated GPU and an NVIDIA card, the simulator can end up rendering on the wrong GPU. On a Ryzen X3D CPU with two chiplets, only one has the 3D V-Cache, and a game can land on the other. The test machine solves both with a small script named game, put before %command% in the launch options. This is an example for that machine, not a requirement, and its CPU numbers and GPU names are the test machine's. Change them for yours.

#!/bin/sh
[ $# -gt 0 ] || { echo "usage: game <command> [args]" >&2; exit 2; }

export __NV_PRIME_RENDER_OFFLOAD=1
export __GLX_VENDOR_LIBRARY_NAME=nvidia
export __VK_LAYER_NV_optimus=NVIDIA_only
export VK_DRIVER_FILES=/usr/share/vulkan/icd.d/nvidia_icd.json:/usr/share/vulkan/icd.d/radeon_icd.json
export DXVK_FILTER_DEVICE_NAME=NVIDIA
export VKD3D_FILTER_DEVICE_NAME=NVIDIA
unset DRI_PRIME __EGL_VENDOR_LIBRARY_FILENAMES

exec env -u LD_LIBRARY_PATH -u LD_PRELOAD \
  systemd-run --user --scope --quiet --collect --slice=games.slice -- \
  env LD_LIBRARY_PATH="${LD_LIBRARY_PATH-}" LD_PRELOAD="${LD_PRELOAD-}" "$@"

Save it as ~/.local/bin/game or in another folder of your PATH, and make it executable. It does two things.

  • It points the game at the NVIDIA GPU: the three PRIME offload variables, the Vulkan driver list, and the device name filters of DXVK and vkd3d-proton.
  • It runs the game in a systemd user slice, games.slice. On the test machine that slice has AllowedCPUs=0-7,16-23, the CPUs of the chiplet with the 3D V-Cache, and everything that isn't a game is kept on the other one, 8-15,24-31. You have to make the slice yourself, with the CPUs of your own CPU. This page doesn't claim a gain from it.

The last three lines clear the Steam runtime's library variables for systemd-run, which runs without those libraries, and give them back to the game. The script then runs env with what is left of the line, which is why NAME=value options written after game still apply. Options before it apply as well. Steam also passes the game's command to it, so keep game right before %command%.

If you write the three PRIME variables again in the launch options, nothing changes: the script exports the same ones.

One trap, from 11 November 2026. A Steam client update put each game in a systemd scope of its own, app-steam-app<id>-<pid>.scope, in app.slice, and the game left games.slice. Twenty-two starts of the simulator ran without the V-Cache until it was found. A drop-in at ~/.config/systemd/user/app-steam-.scope.d/slice.conf with these two lines fixed it:

[Scope]
Slice=games.slice

Check it with the simulator open: grep Cpus_allowed_list /proc/<pid of the simulator>/status must show the CPUs you chose. A machine with two GPUs has a second cost: the GPU that composes the desktop. The ground rules have the measurement.

MFG Unlocker with XMX

The MFG Unlocker guide has the full text. The options, in short:

  • WINEDLLOVERRIDES="version=n,b": Wine would load its own version.dll and never the mod's. If your line has WINEDLLOVERRIDES already, add version=n,b to it.
  • PROTON_NVIDIA_NVCUDA=1: the mod takes its GPU route only when CUDA answers, and Proton leaves CUDA off without this. Without it the mod's log says capability=0.0 verified=0.
  • PROTON_DLSS_UPGRADE=1, as above.
  • __GL_0xcfcfa1=0, optional: an internal setting of NVIDIA driver 620.70.06 that turns off the driver's background shader compile threads. With XMX, the simulator's video memory budget otherwise fell from about 15 GB to 13.7 to 14.4 GB. With it, the budget stayed near 15 GB in a flight on 12 November 2026. It is specific to that driver version. What it costs the rest of the simulator wasn't measured beyond the frame pace.
  • VKD3D_SWAPCHAIN_LATENCY_FRAMES=2, optional: with XeLL sleep on, the mod holds vkd3d-proton's low latency mode off, so vkd3d-proton's own limiter holds the swap chain queue at 3 frames by default, on every Present, generated frames included. 2 removes one frame, 8.3 ms at 4x on a 120 Hz screen. It felt better in a flight on 11 November 2026. vkd3d-proton's own comment warns that a short queue can make the GPU clock drop in some games, and with 1 the output left 120 on the test machine.
  • VKD3D_SWAPCHAIN_PRESENT_MODE=MAILBOX, only if the picture tears with V-Sync on. It needs a Wayland window and a driver that offers MAILBOX for it.

With XeLL sleep on, you don't need VKD3D_DISABLE_EXTENSIONS=VK_NV_low_latency2 any more.

Preferences

These are choices of the test machine's owner. They aren't needed, and they cost something or haven't been measured against the alternative.

DLSS Super Resolution preset M, recommended on NVIDIA

PROTON_DLSS_UPGRADE=1 DXVK_NVAPI_DRS_SETTINGS=ngx_dlss_sr_override=on,ngx_dlss_sr_override_render_preset_selection=render_preset_m

The simulator's DLSS goes through dxvk-nvapi, which reads driver settings from DXVK_NVAPI_DRS_SETTINGS. This pair forces preset M. The owner prefers it and recommends it on NVIDIA GPUs. On 15 October 2026 the DLSS indicator showed Render Preset: M, DLSS 310.9.16 marked nvapp_override, and Quality at 2560x1440 for a 3840x2160 screen, and the owner saw jagged edges and ghosting on the panels improve a lot.

  • Write the value in full, render_preset_m. With plain m, the override turns on and the preset is dropped without a warning. default sets 0x0.
  • With PROTON_DLSS_UPGRADE=1 Proton fills this variable with the preset default, but yours wins.
  • The variable takes a comma-separated list. If your line has it already, add these two settings to its list.
  • The simulator's own nvngx_dlss.dll is version 310.6.0.0, and whether it has preset M wasn't checked. The upgrade guarantees a file that has it.
  • Some setups also force a DLSS frame generation preset here, ngx_dlss_fg_override=on,ngx_dlss_fg_override_render_preset_selection=render_preset_c. This page doesn't recommend it. The owner decided on 12 November 2026 to take it out. The drop in frame rate with presets A and B came from the Reflex sleep under VK_NV_low_latency2, not from the preset: without the extension the output held 120 in every preset. And under XMX the mod doesn't use NVIDIA's generator preset.

ReBAR off for the simulator

VKD3D_CONFIG=no_upload_hvv,no_gpu_upload_heap

On the test machine the NVIDIA driver keeps ReBAR on for the whole card (nvidia-smi -q -d MEMORY showed a BAR1 of 16,384 MiB), and vkd3d-proton decides whether to use the memory the CPU can see. no_upload_hvv stops the upload heap from using it. no_gpu_upload_heap turns off the GPU_UPLOAD_HEAP that the game asks for. With only the first, that path stays. On 16 October 2026 the vkd3d-proton log said Forcing HOST_COHERENT for UPLOAD heap instead of HVV usage is allowed, and the owner saw 1 to 2 GB less video memory in use in the same scene. vkd3d-proton's README warns that the option costs GPU performance. The frame rate of that flight went up, together with the DLSS frame generation preset C, and nobody measured each one alone.

One line for each profile

Copy the one that fits, and add your own STEAM_COMPAT_LIBRARY_PATHS if you use ChasePlane. Each line stands alone.

An NVIDIA GPU, X11 driver

PROTON_DLSS_UPGRADE=1 DXVK_NVAPI_DRS_SETTINGS=ngx_dlss_sr_override=on,ngx_dlss_sr_override_render_preset_selection=render_preset_m %command%

An NVIDIA GPU, Wayland session, HDR monitor

PROTON_ENABLE_WAYLAND=1 PROTON_ENABLE_HDR=1 WAYLANDDRV_FOCUS_LOSS=0 PROTON_DLSS_UPGRADE=1 DXVK_NVAPI_DRS_SETTINGS=ngx_dlss_sr_override=on,ngx_dlss_sr_override_render_preset_selection=render_preset_m %command%

The same, with the game script for two GPUs or an X3D CPU

PROTON_ENABLE_WAYLAND=1 PROTON_ENABLE_HDR=1 WAYLANDDRV_FOCUS_LOSS=0 PROTON_DLSS_UPGRADE=1 DXVK_NVAPI_DRS_SETTINGS=ngx_dlss_sr_override=on,ngx_dlss_sr_override_render_preset_selection=render_preset_m game %command%

MFG Unlocker with XMX

WINEDLLOVERRIDES="version=n,b" PROTON_NVIDIA_NVCUDA=1 PROTON_DLSS_UPGRADE=1 __GL_0xcfcfa1=0 VKD3D_SWAPCHAIN_LATENCY_FRAMES=2 %command%

All of it together, for a machine like the test machine

__GL_0xcfcfa1=0 VKD3D_SWAPCHAIN_LATENCY_FRAMES=2 WINEDLLOVERRIDES="version=n,b" PROTON_NVIDIA_NVCUDA=1 PROTON_ENABLE_WAYLAND=1 PROTON_ENABLE_HDR=1 PROTON_DLSS_UPGRADE=1 DXVK_NVAPI_DRS_SETTINGS=ngx_dlss_sr_override=on,ngx_dlss_sr_override_render_preset_selection=render_preset_m VKD3D_CONFIG=no_upload_hvv,no_gpu_upload_heap VKD3D_SWAPCHAIN_PRESENT_MODE=MAILBOX WAYLANDDRV_FOCUS_LOSS=0 game %command%

Drop what doesn't fit your machine: __GL_0xcfcfa1=0 if your driver isn't 620.70.06, PROTON_ENABLE_HDR=1 without an HDR monitor, game without the script, and VKD3D_SWAPCHAIN_PRESENT_MODE=MAILBOX if nothing tears.
