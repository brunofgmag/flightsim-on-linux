Navigraph Simlink

Tested with Navigraph Simlink 1.1.41 on 30 October 2026. It runs in a Wine prefix of its own with the Wine of your distribution, not in the simulator's prefix, so it takes several steps: the install, the SimConnect port, a link handler for the sign-in, and an optional watcher.

touches add-on files The fix writes SimConnect.cfg beside NavigraphSimlink.exe, in Simlink's own folder. A SimConnect.cfg that was already there is kept in compatdata/2537590/flightsim-on-linux-backup/navigraph-simlink/cfg, and this puts it back, or removes the one the fix wrote:

~/flightsim-on-linux/bin/flightsim-on-linux addon undo navigraph-simlink

Get it

Simlink is Navigraph's program, and it needs a Navigraph account. The installer is Navigraph+Simlink.exe, an Inno Setup 6.2.2 installer, version 1.1.41. The address to download it from isn't recorded here. Simlink sends the aircraft's position to Navigraph Charts. It needs no plugin in the simulator, and works with MSFS 2020 and 2024.

Install it

Install the wine package of your distribution first. The test machine used Wine 11.20 from Arch's wine. This add-on uses neither Proton nor the simulator's prefix. Then give the installer to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install navigraph-simlink ~/Downloads/Navigraph+Simlink.exe

Without the file name it only prints where to get the program. With it, the command makes a new prefix in ${XDG_DATA_HOME:-~/.local/share}/flightsim-on-linux/navigraph-simlink with wineboot -i, then runs the installer in it with /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- /LOG=C:\simlink-install.log. It installs into C:\Program Files\Navigraph\Simlink of that prefix. It refuses while Simlink is open.

The command runs Wine with its menu builder switched off. A new prefix of the system Wine otherwise writes into ~/.local/share/applications six file associations (.chm, .crt, .hlp, .msp, .reg, .vbs) that open those files in the Simlink prefix, a handler for navigraph-traffic-desktop that competes with the one this add-on sets, and a menu entry that opens Simlink without the launch script. On 18 October 2026 all of them had to be deleted by hand.

Why a prefix of its own: in the simulator's prefix, the Wine there doesn't run the Run registry key, and a program opened outside the simulator's container competes with it for the prefix, so Simlink opened only by hand, after the simulator. In its own prefix it opens at login and finds the simulator over TCP.

Make it run

Three commands, in this order. The first needs the simulator closed.

~/flightsim-on-linux/bin/flightsim-on-linux addon apply simconnect-tcp
~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut navigraph-simlink
~/flightsim-on-linux/bin/flightsim-on-linux addon apply navigraph-simlink

The last one does two things, and fails with the command to run when something is missing:

  • It writes SimConnect.cfg next to NavigraphSimlink.exe, with Protocol=IPv4, Address=127.0.0.1 and the port that SimConnect.xml declares. A SimConnect client finds the simulator through a pipe, which lives on the simulator's Wine server and which a program in another prefix can't see, or through a SimConnect.cfg. Simlink has the client inside its exe. On 18 October 2026, with a SimConnect.cfg pointing at port 5112 and a listener on that port, it looked in its own folder, in Documents and in Public Documents, tried the pipe, then connected to 5112 every 6 seconds until the server answered. So it can open before the simulator. The file is not in Documents, because in a prefix of the system Wine, Documents is a link to your home folder. simconnect-tcp is what moves the simulator's port from 500, which Linux doesn't let it open, to 5111.
  • It makes the menu entry the handler for the sign-in link. The Sign in button opens Navigraph's page in your browser, and the page ends by calling navigraph-traffic-desktop://oidc_sign_in_redirect?.... On Windows that starts a second copy of the exe with the link, and the copy hands the code to the first through a named pipe. Without a handler on Linux nothing happens, and Simlink sits at "Please wait for user authentication". The command runs xdg-mime default for that link scheme, so the menu entry's launch script gets the link. It starts the second copy in the same prefix, which finds the first because the pipe lives on that prefix's Wine server. On 18 October 2026 the log recorded OIDC_authorization_code_flow and the login went through. apply remembers the handler you had before, and addon undo puts it back.

The launch script does two more things, which you don't have to set up. It starts Simlink with QT_OPENGL=software, because Simlink is a Qt 5 program and the package brings opengl32sw.dll. Started that way it drew its login window and didn't show in nvidia-smi. And it sends the program's output to /dev/null, because Simlink prints the access token and the refresh token of your Navigraph account there. Don't add a log. It also refuses any argument that isn't a navigraph-traffic-desktop: link.

Start it

The menu entry you wrote before is called "Navigraph Simlink". It starts Simlink in its prefix, and with Simlink already open it says so and does nothing. It doesn't need the simulator.

To open Simlink when you log in, as Windows does:

~/flightsim-on-linux/bin/flightsim-on-linux addon launch navigraph-simlink autostart

This writes flightsim-on-linux-navigraph-simlink.desktop in ~/.config/autostart. addon launch navigraph-simlink autostart -- --remove takes it out. On KDE, on 25 October 2026, with the test machine's own autostart entry, the machine started at 12:24:19 and the Simlink process at 12:24:36, 17 seconds later, with no simulator. Other desktops weren't tested.

To restart Simlink when it stops talking to the simulator:

~/flightsim-on-linux/bin/flightsim-on-linux addon watcher navigraph-simlink

Simlink has a bug. When its connection to the simulator drops, it keeps the error as a positive number (0x40, ERROR_NETNAME_DELETED), takes it for success, and never reconnects. On 30 October 2026 at 20:53, with the simulator open since 20:14, the Navigraph chart didn't show the aircraft. Simlink had no TCP connection at all, not even to the cloud, but kept renewing its token every 45 minutes. A restart fixed it: at 21:02 the new Simlink connected in under 3 seconds with the same simulator.

The watcher is a user service called flightsim-on-linux-navigraph-simlink.service. It looks every 10 seconds. When Simlink is running, the simulator is listening on the SimConnect port, and Simlink has had no connection to it for 60 seconds, it runs the add-on's restart script. That script closes Simlink by force, with taskkill /f in Simlink's own prefix and nowhere else, waits for it to go, and starts it again. It restarts at most three times per simulator, and it never starts Simlink by itself and never stops it. Simlink hasn't hung in front of the watcher yet: it was tested with a fake Wine and a fake launcher in both directions, and the restart itself was done by hand.

The watcher watches port 5111, written in the add-on's addon.json because a watcher setting can't read SimConnect.xml. That is the port simconnect-tcp sets. If your SimConnect.xml declares another port, addon check fails and names the setting watcher.health.connected_to, so you can change it to match.

The Simlink log, AppData\Roaming\Navigraph\Simlink\logs\simlink_<date>.dlog in the prefix, doesn't record connections, so it can't tell you whether Simlink is connected. This does, with Simlink and the simulator open:

ss -tnp | grep NavigraphSimlin

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check navigraph-simlink

It prints six lines, each starting with ok or FAIL, and changes nothing, so you can run it with the simulator open:

  • Wine is installed;
  • NavigraphSimlink.exe is in the prefix;
  • SimConnect.xml declares a port above 1023;
  • SimConnect.cfg points at that port;
  • the watcher watches that port;
  • the sign-in link opens the menu entry.

Each failing line names the command that fixes it.

Known problems

  • Simlink never reconnects after a drop, as above. What dropped the connection on 30 October 2026 wasn't measured. Whether Windows hands this callback an NTSTATUS instead of a Win32 error, which would make a Wine patch the real fix, is a guess from the binary and nothing more.
  • The log doesn't record connections, as above.
  • The Quit item of the tray menu closed a stuck Simlink in about a second. How the menu opens for someone who clicks the bar wasn't seen.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo navigraph-simlink
~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut navigraph-simlink --remove
~/flightsim-on-linux/bin/flightsim-on-linux addon watcher navigraph-simlink --off
~/flightsim-on-linux/bin/flightsim-on-linux addon launch navigraph-simlink autostart -- --remove

The first removes SimConnect.cfg and gives the sign-in link back to the program that had it before. The prefix stays, with Simlink and your login in it. To delete it, quit Simlink and run rm -r ~/.local/share/flightsim-on-linux/navigraph-simlink.
