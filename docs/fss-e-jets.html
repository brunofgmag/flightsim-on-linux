FSS E-Jets

Tested with the FSS E-Jets 1.0.2 on 15 October 2026. Nothing Linux-specific is needed beyond the store they come from: the aircraft is a set of MSFS packages that runs entirely inside the simulator.

Get it

The E-Jets come from the Contrail store, as two packages: fss-aircraft-e19x for the E190 and E195, and fss-aircraft-e19xfreighter for the freighters. This guide doesn't have the store page, so look in the store. addon install fss-e-jets only prints where it comes from.

Install it

Install the packages with Contrail, as on Windows. Close the simulator and every other program of its prefix first. The ground rules explain why. Contrail is a Windows program, and it needs a few things before it opens and closes properly under Proton: its guide has them. The E-Jets themselves needed nothing. On 14 October 2026 Contrail 2.4.6 installed both packages on the test machine. Make sure Contrail puts them in your Community folder; the check below tells you if it didn't.

~/flightsim-on-linux/bin/flightsim-on-linux addon install fss-e-jets

That command prints the store and the kind of installer, and runs nothing.

Make it run

Nothing. The aircraft is WASM only and needs no Proton FS2024 patch and no setting in the prefix. It was tested on Proton FS2024, and stock Proton was not tried. addon apply fss-e-jets says there is nothing to apply and then runs the check.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check fss-e-jets

It prints one line for each of the two packages that is in your Community folder, starting with ok and giving the version, and it changes nothing. It prints FAIL when neither package is there, when a package is a link to a folder that is gone, or when a package has no readable manifest.json. You may own only one of the two packages, and then you get one line.

Known problems

  • navdata-updater.exe, in the root of each package, crashes about a second after its window opens. On 15 October 2026 it did so every time, in the same place (it reads from a null pointer), both with the simulator closed under the X11 driver and with the simulator running inside its container. Users report that it opens on Windows, and why it fails here wasn't found. You don't need it.
  • Download the navdata from the aircraft's own EFB instead, once for each package. The E190 and the E195 share the navdata of fss-aircraft-e19x, and the two freighters share that of fss-aircraft-e19xfreighter. The EFB saves the new file in the package's WASM work folder, and the aircraft loads it on the next flights. On the test machine the freighter shipped with the 2503 AIRAC, and the EFB downloaded 2610 on 15 October 2026.
  • The X button of the Contrail window does not close it. Use the close action of its menu entry, which its guide describes.

Undo

addon undo fss-e-jets has nothing to restore, because nothing was changed. Remove the aircraft with Contrail.
