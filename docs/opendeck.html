OpenDeck for Stream Deck

Tested with OpenDeck 2.14.2 on 22 October 2026. It is a native Linux program, so it doesn't go into the simulator's prefix and needs no fix to run. This guide covers the parts around it: moving your profiles over from the Windows Stream Deck app, three optional patches to its source, and the plugin for Lorby's Axis and Ohs. Only that plugin step changes a file that isn't yours, and its section says how to undo it.

Get it

OpenDeck is free, open-source software (the project is nekename/OpenDeck on GitHub). The test machine uses the opendeck package of Arch Linux, 2.14.2-1.1. Install it from your distribution if it has one:

sudo pacman -S opendeck
~/flightsim-on-linux/bin/flightsim-on-linux addon install opendeck

The second command only prints where to get it and what kind of program it is.

Bring your profiles from the Windows Stream Deck app

OpenDeck doesn't import the profiles of the Elgato app. convert-profiles does, from a copy of the Windows app's data folder, %APPDATA%\Elgato\StreamDeck, the one that holds ProfilesV3 and Plugins. It reads that folder and never changes it.

Before you run it:

  • Close OpenDeck, and copy ~/.config/opendeck somewhere safe. The converter writes into it.
  • Find the OpenDeck name of each device. OpenDeck calls a device sd- followed by its serial number, and the same name is the folder under ~/.config/opendeck/profiles once the device has been connected.
  • Know the Elgato model of each: 20GBD9901 is the Stream Deck +, 20GAT9902 the XL and 20GBA9901 the MK.2. Other models are left out because their size isn't in the converter, and it says so.
~/flightsim-on-linux/bin/flightsim-on-linux addon launch opendeck convert-profiles -- \
  --source /path/to/StreamDeck --config ~/.config/opendeck --report ~/opendeck-report.json \
  --device 20GBD9901=sd-SERIAL-OF-YOUR-PLUS --device 20GBA9901=sd-SERIAL-OF-YOUR-MK2

Give one --device for each device you own. A profile for a model with no --device is left out and listed in the report. Other options: --skip NAME leaves a profile out (repeat it), for example the profiles of another simulator; --adapted FOLDER installs the .sdPlugin folders in it first; --gpu-selector and --network-interface fill in the Redline plugin's settings for the System Vitals buttons that show a GPU or the network.

What it does:

  • OpenDeck has neither pages nor folders, so each page becomes a profile named Name/Page 01, and each folder Name/Folder 01 Title, inside a group named after the Elgato profile. A dot in a name becomes a dash, because OpenDeck uses the dot as a separator.
  • Next page, previous page, go to page, open folder, back and switch profile become the Starter Pack's "Switch Profile" button. A hotkey or a text button becomes its "Input Simulation".
  • The images are copied under ~/.config/opendeck/images: 6,001 images, about 140 MB, on the test machine. A title saved without alignment and size gets top and 11. That matched how a button looked in the Windows app on the test machine; nothing in the profiles says which default the Elgato app uses.
  • Plugins that the profiles use are copied from the Windows app, unless OpenDeck already has one by that name. Replacements are mapped for the Elgato Discord, Volume Controller and System Vitals plugins, if you installed the OpenDeck plugin that replaces each.
  • Each device opens on Default Profile/Page 01.

What it can't carry over goes in the report, by reason, and every button is counted. On the test machine 10,454 buttons converted and 103 had no equivalent: an action stack keeps only its active action, a few built-in actions have no match, and 13 plugins bought on the Elgato marketplace have encrypted manifests that OpenDeck can't read.

Three optional patches to OpenDeck

These change OpenDeck's source and give you a binary of your own. You can skip all of this. The patches are in addons/opendeck/patches:

  • swipe-changes-the-page.patch: OpenDeck 2.14.2 drops a swipe on the Stream Deck + touch strip. With the patch a swipe changes to the next or previous Page NN profile of the same group, the names the converter writes. It has not been seen working on the device.
  • strip-render-no-checkerboard.patch: this one is for another project, streamdeck-strip-render, which draws the touch strip. It paints a grey checkerboard over any image slot that has no image. The Axis and Ohs dials, with the $A0 layout, have a slot that the plugin never fills, and the checkerboard showed on every dial. The Elgato app draws nothing there. The patch draws nothing too.
  • dial-title-like-elgato.patch: OpenDeck ignored "show title" on dials and trimmed a title of a single space to nothing, which brought back the action's name over the plugin's own text. The patch follows the Elgato app: a hidden title leaves the title blank, a title of only spaces stays blank, and only an empty one falls back to the action's name. A title sent by the plugin wins over the saved one when titles are shown.

To build OpenDeck with all three you need git, npm and cargo (rust on Arch), and some time and disk for the build:

~/flightsim-on-linux/bin/flightsim-on-linux addon launch opendeck rebuild -- 2.14.2

Without a version it uses the one pacman says is installed. The script clones OpenDeck and streamdeck-strip-render into ~/.cache/flightsim-on-linux/opendeck, checks out the tag, applies the patches, installs the front end, runs OpenDeck's encoder_layouts tests and builds. It stands in for the deno that OpenDeck's build calls with one that does nothing. So the binary doesn't carry the plugins that come with OpenDeck. It takes them from the package's folder, /usr/lib/opendeck/plugins, and it won't work where that folder doesn't exist.

It ends by printing where the binary is and the command to install it:

sudo install -m 755 ~/.cache/flightsim-on-linux/opendeck/source/src-tauri/target/release/opendeck /usr/bin/opendeck

OpenDeck uses the new binary at its next start. A package update puts the stock one back, so run rebuild again after it. On the test machine a pacman hook did that by itself, as a transient systemd service. That hook needs root and is not part of this repository.

The Axis and Ohs plugin

Lorby's plugin for Stream Deck, com.lorbysi.aao.sdPlugin (71.01 here), is an HTML plugin. In OpenDeck it runs in OpenDeck's own web view, which serves it from http://127.0.0.1:57118, and it asks AAO's web API at http://localhost:43380/webapi from a different origin. The web view therefore applies CORS to every answer. AAO runs in wine-mono and sends Access-Control-Allow-Origin: * twice. WebKit joins them into *, *, an invalid value, and hands every answer to the plugin as an error. The plugin tests the connection every 500 ms with GET ?conn=1, the load event never fires and it never connects, so the connection button stays dark with AAO running. The plugin also sends Cache-Control: no-cache, which forces a preflight OPTIONS request. AAO answers it with 405 and doesn't list that header as allowed. On Windows the Stream Deck app doesn't do this check, which is why it only shows up here.

The fix is a small proxy in front of AAO that sends each header once and answers the preflight with 204, plus the plugin pointed at it. The proxy is part of the Axis and Ohs guide, on port 43390. Pointing the plugin is one line of its settings.js:

touches add-on files This is the only step of this guide that changes a file of a plugin: aao-plugin edits one line of the plugin's settings.js and keeps the plugin's own file as settings.js.orig beside it. This puts the original back:

~/flightsim-on-linux/bin/flightsim-on-linux addon launch opendeck aao-plugin -- --restore
~/flightsim-on-linux/bin/flightsim-on-linux addon launch opendeck aao-plugin

That moves the port from 43380 to 43390 (or to the number you give it), and keeps the plugin's own file as settings.js.orig. aao-plugin --restore puts it back. A new version of the plugin brings 43380 back, and the check says so.

A dark Axis and Ohs button with an empty title is not always CORS. With no SimConnect connection AAO answers 0 to every variable and takes about 150 ms for each one it is asked, and the plugin gives up after 500 ms. Reading (A:TITLE, String) through the API tells them apart: an empty title is AAO without SimConnect. Windows plugins in general run in the system Wine, in ~/.wine, far from the simulator's prefix. Their processes also start with C:\, so to count the prefix's programs, filter by compatdata/2537590 in /proc/<pid>/environ.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check opendeck

It prints two or three lines, each starting with ok or FAIL, and changes nothing:

  • opendeck is installed, and where;
  • what binary it is. It is the patched build that rebuild made when its checksum matches the one rebuild recorded. It fails when a record exists and the binary is something else, which is what a package update does. Without a record it says the binary is the stock one, or, when pacman -Qkk opendeck reports that file as changed, that somebody changed it;
  • only when the AAO plugin is in OpenDeck's plugins folder: it doesn't use AAO's own port 43380.

On the test machine pacman -Qkk opendeck reports a wrong SHA256 for /usr/bin/opendeck, which is how a patched binary shows when it was built by something other than rebuild.

Known problems

  • A new binary is used at the next start of OpenDeck. A running process keeps what it loaded.
  • The swipe has never been seen working on the device.
  • 13 plugins from the Elgato store have encrypted manifests that OpenDeck can't read. Some have a native Linux replacement.
  • rebuild was exercised in this repository with stand-in tools and against the real source files with git apply, and the binary on the test machine came from the script it was ported from. A full build from this copy of the script has not been run.

Undo

addon undo opendeck has nothing to restore, because apply changed nothing. To go back from a patched binary to the stock one, reinstall the package (sudo pacman -S opendeck). To put the AAO plugin back, run addon launch opendeck aao-plugin -- --restore. To undo a conversion, put back the copy of ~/.config/opendeck that you made.
