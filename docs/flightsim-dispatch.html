FlightSim Dispatch

Tested with FlightSim Dispatch 1.5.0.2 on 17 October 2026. It comes as a zip, runs in a Wine prefix of its own and needs no fix.

Get it

FlightSim Dispatch is a database of real flights from the 1950s to today. You search by airport, airline, aircraft, duration and year to pick a real route to fly. The program's own window says it is distributed by flightsimdispatch.net. The file is FlightSimDispatch.1.5.0.2.zip, a PyInstaller and PyQt5 program with a 543 MB SQLite database, FlightDB.db, next to it. The price wasn't recorded.

Install it

Install the wine package of your distribution first. The test machine used Wine 11.20 from Arch's wine. This add-on uses neither Proton nor the simulator's prefix. FlightSim Dispatch never talks to the simulator: on 17 October 2026, strings -n 6 FlightSimDispatch.exe | grep -ci simconnect printed 0, and the libraries packed into it are Python 3.14, Qt 5, OpenSSL and SQLite. So none of the simulator prefix's rules apply to it. Then give the zip to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install flightsim-dispatch ~/Downloads/FlightSimDispatch.1.5.0.2.zip

Without the file name it only prints where to get the program. With it, the command:

  • makes a Wine prefix in ${XDG_DATA_HOME:-~/.local/share}/flightsim-on-linux/flightsim-dispatch with wineboot -i, if it doesn't exist, with Wine's menu builder switched off so the new prefix writes no file associations into ~/.local/share/applications;
  • unzips the file into drive_c/FlightSimDispatch of that prefix;
  • refuses while FlightSim Dispatch is open.

To update, run the same command with the new zip. The zip carries a note that says to delete all the files and unzip into a clean folder, so the command replaces the whole folder. It unzips into a side folder first, and a file that isn't the FlightSim Dispatch zip leaves the installed folder as it was. This install doesn't touch the simulator's prefix, so the command doesn't ask you to close anything there.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply flightsim-dispatch

This changes nothing, and then runs the check. FlightSim Dispatch needs no Proton patch, no registry value and no setting.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut flightsim-dispatch

This writes an entry called "FlightSim Dispatch" in your application menu. It has the default icon, because the program's icon sits in a resource that 7z can't open. The entry starts the program from its own folder, with the simulator open or closed, and with the program already open it says so and does nothing. Wine's output goes to ~/.cache/flightsim-on-linux/logs/flightsim-dispatch.log. The program checks its version over the network when it starts, and on 17 October 2026 it answered "FS Dispatch is up to date!".

On 17 October 2026, with this setup, a search from SBGR filled the route table after "Refresh Table", and a flight clicked in the table showed its details with the accents right ("São Paulo Guarulhos International Airport").

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check flightsim-dispatch

It prints three lines, each starting with ok or FAIL, and changes nothing: Wine is installed, and FlightSimDispatch.exe and FlightDB.db are in the prefix's folder. When one fails, run the install command again.

Known problems

  • The log fills with MESA-EGL: warning: egl: failed to create dri2 screen. Qt looks for OpenGL on the NVIDIA card through Mesa and doesn't find a screen. The warnings are harmless: the window draws and everything above worked with them.

Undo

Take out the menu entry:

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut flightsim-dispatch --remove

addon undo flightsim-dispatch has nothing to restore, because apply changed nothing. To delete the program and its prefix, close it and run rm -r ~/.local/share/flightsim-on-linux/flightsim-dispatch.
