RenoDX HDR for MSFS 2024

Tested with version 1 of the RenoDX HDR mod for Microsoft Flight Simulator 2024, from Nexus Mods (mod 26), on 5 November 2026, and next to AtmosphereMod 0.7.1 on 9 November 2026. It is a ReShade add-on by HDRgameAnalysis, built on ShortFuse's RenoDX. It lowers the raised black level of the game's HDR and adds sliders for peak brightness, paper white and UI brightness. Alone it needs ReShade and HDR on. Next to AtmosphereMod it replaces nothing until AtmosphereMod moves its parameters out of the register space RenoDX uses. Since 0.7.0, AtmosphereMod's own installer does that when it gets --renodx.

touches add-on files apply edits AtmosphereMod's settings only when AtmosphereMod is older than 0.7.0: it sets InjectGraphicsRootSignature under [ATMOSPHEREMOD] in ReShade.ini from 1 to 0, when AtmosphereMod injects and puts its parameters in the same place as RenoDX. The first time, it keeps the value it replaced in compatdata/2537590/flightsim-on-linux-backup/renodx-hdr, and this puts it back:

~/flightsim-on-linux/bin/flightsim-on-linux addon undo renodx-hdr

Get it

The mod is free and has one source, its page on Nexus Mods, which you open in a browser. No command here can fetch it. Download the zip from the Files tab.

  • The zip that was tested has sha256 226df85c594e8ef6cfb4d416d2bb20d598b32e927d60f6f0a914a0605c3b4af2. It holds README.txt, LICENSE.txt and renodx-msfs2024.addon64.
  • renodx-msfs2024.addon64 has sha256 304008e72d2fa6a9efe23bea527dec79525ae82decd7c16ef0c36bb27eeecb7e. ReShade logs it as Registered add-on "RenoDX" v0.2026.1101.238.

The licence is MIT: the RenoDX framework is copyright 2025 Carlos Lopez Jr. (ShortFuse) and the mod is copyright 2026 HDRgameAnalysis. The author tested it on the Microsoft Store version 1.9.21.0. The test here was the Steam version. The README warns that a game update can change the game's shaders and stop the mod until it is updated.

Install it

Install ReShade first, version 6.8.0 or newer, with add-on support. The simulator has to be closed. Without a file, the command prints where to get the mod:

~/flightsim-on-linux/bin/flightsim-on-linux addon install renodx-hdr

Then give it the zip you downloaded, or the .addon64 inside it:

~/flightsim-on-linux/bin/flightsim-on-linux addon install renodx-hdr /path/to/the-zip

It checks the sha256 of the .addon64, so a re-zipped copy of the same file is fine and another version is not: it is refused, and nothing is installed. It also refuses while the simulator runs, when ReShade's dxgi.dll is not in the simulator's folder, and when another renodx-*.addon64 is there, because the mod's README allows no other RenoDX add-on beside it. Then it copies renodx-msfs2024.addon64 into the simulator's folder, beside dxgi.dll.

HDR has to be on before the simulator starts, because the game picks HDR or SDR at startup. On the test machine ReShade.log showed the swap chain in hdr10_pq.

Make it run

Without AtmosphereMod there is nothing to fix:

~/flightsim-on-linux/bin/flightsim-on-linux addon apply renodx-hdr

says so, changes nothing and runs the check.

With AtmosphereMod, run its install again once RenoDX is in the simulator's folder. On Windows, AtmosphereMod's README says to run Install AtmosphereMod.cmd --renodx. Here the install command adds --renodx itself whenever a renodx-*.addon64 is in the simulator's folder, and prints a line that says so:

~/flightsim-on-linux/bin/flightsim-on-linux addon install atmospheremod
~/flightsim-on-linux/bin/flightsim-on-linux addon apply renodx-hdr

The first command installs AtmosphereMod 0.7.1, the release the AtmosphereMod guide pins. With --renodx, its installer patches the shaders with AtmosphereMod's parameters in register space 51 and writes RegisterSpace=51 under [ATMOSPHEREMOD] in ReShade.ini. The add-on reads the space from that line, and InjectGraphicsRootSignature stays 1, so AtmosphereMod keeps its haze over the ground. Without the option, the installer keeps the space it finds in ReShade.ini, so the reinstall after a simulator update stays in space 51 even without RenoDX in the folder. Without RegisterSpace in ReShade.ini the space is 50. --no-renodx goes back to 50, and this command never passes it. The second command changes nothing once AtmosphereMod is out of space 50, and runs the check.

If AtmosphereMod 0.7.0 or later is still in space 50, apply changes nothing either. It stops with an error that names the install command. If AtmosphereMod is older than 0.7.0, apply turns its graphics injection off instead, as the section below on older releases describes.

A ReShade reinstall can undo this. If it brings a ReShade.ini without the [ATMOSPHEREMOD] section, and AtmosphereMod is then installed without --renodx, AtmosphereMod goes back to space 50. Nothing on the screen says so, and only ReShade.log shows RenoDX failing. Here that happens only when RenoDX is not in the folder at the reinstall. The check catches it.

Why the two clash

With AtmosphereMod in space 50, the mod loads, finds its two shaders and replaces neither. Here is why.

  • RenoDX replaces two pixel shaders, 0x6bc6b2f3 (ph_2d_HDR10) and 0x5244e47d (ph_tonemapping). They belong to the simulator's global graphics root signature, the one with 23 parameters.
  • With InjectGraphicsRootSignature=1, AtmosphereMod adds to that root signature the root constants b0 space50 x16 and a root descriptor u0 space50. RenoDX puts its own constant buffer at b13 space50, the same register space. Up to release 0.6.1 AtmosphereMod's space was fixed at 50.
  • ReShade 6.8.0 hands the root signature to the add-ons one after another, in the order they loaded, and each gets it as the one before changed it. ReShade.log shows AtmosphereMod loading before RenoDX, so RenoDX meets a root signature that already uses space 50 and gives up on it. The log shows Params not created and Failed to replace pipeline, and the image doesn't change.

Three runs on 5 November 2026 tell the cause from the other candidates, and a fourth on 9 November 2026 checks the official fix:

RunAtmosphereModWhat ReShade.log shows
5 Nov, 11:510.5.1, space 50, injection onEvery replacement fails.
5 Nov, 15:490.5.1, InjectGraphicsRootSignature=0will insert cbuffer 13 at root_index 23, 7 lines Replacing pipeline for 0x6bc6b2f3, 2 for 0x5244e47d, no Failed to replace pipeline.
5 Nov, 16:20Private build of 0.5.1 in space 51, injection onwill insert cbuffer 13 at root_index 25, the same 7 and 2 replacements, no Failed to replace pipeline.
9 Nov, 16:240.7.1 with RegisterSpace=51 from --renodx, injection onAtmosphereMod: root parameters in register space 51 (installed with --renodx), will insert cbuffer 13 at root_index 25, the same 7 and 2 replacements, no Failed to replace pipeline.

What decides is the space they share, not the number of parameters. Params not created is not the line to look for: it appears in the runs that worked as well. Failed to replace pipeline is.

For the run on 9 November 2026, the 0.7.0 installer ran with --renodx, then the 0.7.1 installer ran over it without the option. It printed RenoDX: compatible, register space 51 and patched 3079 shaders with none failed. The installers ran with the arguments the install command passes, from a script on the test machine. The repository's own install command was not run with 0.7.1. The numbers above come from the log. Whether the HDR picture and the haze look right on the screen was not judged in that run.

The check and apply find AtmosphereMod's space in three places, in this order. First, logs/layouts.txt in AtmosphereMod's data folder, where a line like [23] root constants b0 space51 x16 dwords is AtmosphereMod's own parameters, if that file is newer than the AtmosphereMod install. That is the space the last run used. Second, RegisterSpace under [ATMOSPHEREMOD] in ReShade.ini, which is what the next run will use. So right after an install with --renodx, before the simulator has run, the check already passes. Third, space 50 is assumed.

With AtmosphereMod older than 0.7.0

An AtmosphereMod older than 0.7.0 has no --renodx. Running addon install atmospheremod updates it to 0.7.1, and that is the better fix. If you keep the older release, apply turns its graphics injection off when AtmosphereMod is installed, InjectGraphicsRootSignature is 1, and its parameters are in space 50. The version comes from install.json in AtmosphereMod's data folder, and a record without a version counts as older. apply changes that one line and keeps every other line and the file's line endings. When a condition fails, it changes nothing and says which.

What it costs

With the injection off, AtmosphereMod can't build the replacement of its ps_deferredRendering pass, which needs the injected root signature. Its events.log says failed to create replacement graphics pipeline for pixel shader ... (is InjectGraphicsRootSignature on?). In the run at 15:49 on 5 November the vkd3d-proton log had 8 errors, dxil-spirv: Failed to remap UAV 50:0, and they are the 8 failures of that pass. That pass is AtmosphereMod's haze over the ground, which goes back to the simulator's own. The sky and the clouds keep the mod.

AtmosphereMod's installer sets the value back to 1 every time it runs, which is after every simulator update. Run apply again after each one. The check fails when you forget.

Before 0.7.0: a private build

From 5 to 9 November 2026 the only way to run both mods with the injection on was a private build of AtmosphereMod 0.5.1 with two constants set to 51: kModSpace in addon/src/atmosphere_mod.cpp and MOD_SPACE in tools/patch_dxil.py, which patches the shaders the installer makes. That build made the run at 16:20 in the table. Section 1c of AtmosphereMod's licence lets you build and run a version with your own changes for private use. Section 2b forbids publishing or sharing a modified version, or a work based on its source. So this repository ships no patch, script or binary for it. Issue 22 on AtmosphereMod's GitHub asked its author to make the space a setting, with 50 as the default. Release 0.7.0 did that with --renodx, and the private build is no longer needed.

Start it

There is nothing to start. The add-on loads with the simulator. Press Home to open ReShade and set everything in its RenoDX tab, as the mod's README says.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check renodx-hdr

It prints five lines, each starting with ok or FAIL, and a sixth once there is a log to read, and it changes nothing. The five are:

  • ReShade's dxgi.dll is in the simulator's folder;
  • renodx-msfs2024.addon64 is there (one line), and its sha256 is the tested one (another line). Another hash fails and says the add-on is untested with that file;
  • no other RenoDX add-on is there;
  • if AtmosphereMod is installed: it passes when AtmosphereMod's parameters are outside space 50, by the three places above, or when InjectGraphicsRootSignature is 0. It fails otherwise, with the command to run: addon install atmospheremod for 0.7.0 and later, and that or addon apply renodx-hdr for an older release. If AtmosphereMod is not installed, the line says nothing clashes.

The sixth line comes from ReShade.log, when it shows RenoDX registered. It fails on Failed to replace pipeline, and it passes on will insert cbuffer, with the root index. The log is the last run's, so the check reads it only when it is newer than the add-on files, AtmosphereMod's install and the last apply. Otherwise the line says the log is older than the last change, and the way to settle it is to start the simulator once and run the check again.

On 9 November 2026, with AtmosphereMod 0.7.1 in space 51, the check printed six ok lines on the test machine.

Known problems

  • An AtmosphereMod older than 0.7.0 has no --renodx, and the fix for it costs the ground haze.
  • A ReShade reinstall that drops the [ATMOSPHEREMOD] section, followed by an AtmosphereMod install while RenoDX is not in the folder, puts AtmosphereMod back in space 50 without a word on the screen.
  • A simulator update can change the shaders RenoDX looks for, and the mod stops until its author updates it.
  • The result was judged by eye on an HDR screen on 5 November 2026. The picture itself was not measured, and neither was the frame rate.
  • The mod's README allows no other RenoDX add-on in the same folder, its DevKit included.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo renodx-hdr

This puts InjectGraphicsRootSignature back to the value it had before the first apply, one line only, and nothing else in ReShade.ini changes. Without a saved value it says there is nothing to undo. If AtmosphereMod's section is no longer in the file, it writes nothing. It leaves RegisterSpace alone: that belongs to AtmosphereMod's installer, and --no-renodx on Windows is how its README puts space 50 back. The add-on itself stays. To remove it, delete renodx-msfs2024.addon64 from the simulator's folder, and its section in ReShade.ini if you want that gone too.
