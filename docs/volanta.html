Volanta

Tested with Volanta 1.19.2 on 30 October 2026. Volanta doesn't run on the simulator's Wine server: it gets a second Wine prefix of its own, so this takes the most steps.

Get it

Volanta's site, volanta.app, serves a Linux AppImage, and that build can't reach MSFS. The flight data comes from a connector, VolantaPlugin_x64.exe, that the app downloads and runs, and the scanner that finds MSFS 2024 looks for UserCfg.opt from LOCALAPPDATA, a variable that exists only inside Wine. You need the Windows build.

The Windows build is listed in the update channel of the app itself. Open https://api.volanta.app/api/v1/ClientUpdate/latest.yml in a browser: it gives the address of volanta-1.19.2.exe (or a newer one) and its SHA-512. Use a browser. The site and its CDN answer curl with 403 from Cloudflare. The installer is an electron-builder one.

Install it

Close the simulator and every program in its prefix first, and run nothing else while the installer works. The ground rules explain why. Then give the installer to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install volanta ~/Downloads/volanta-1.19.2.exe

Without the file name it only prints where to get the program. With it, the command does three things:

  • It refuses to start while the simulator runs or any program is open in the simulator's prefix, and names those programs. It also refuses while Volanta itself is open.
  • It makes the add-ons prefix when it doesn't exist yet. The next section says what that is, and addon apply makes it too, so the order of the two doesn't matter.
  • It runs the installer in the add-ons prefix with /S, the silent mode, and with Wine's PowerShell switched off for that one run. Wine's powershell.exe accepts any command line, prints nothing and exits with zero. The electron-builder installer asks it whether a process is running in the install folder, takes the empty answer for "yes" and stops with a message that it can't close Volanta, even though Volanta was never installed. With /S and no override it exited with code 2. On 14 October 2026, with powershell.exe switched off, it installed the first time.

Volanta goes into C:\users\steamuser\AppData\Local\Programs\Volanta. Because the two prefixes share drive_c, the simulator's prefix sees the same folder.

Make it run

First make the simulator listen for SimConnect clients on TCP, if you haven't:

~/flightsim-on-linux/bin/flightsim-on-linux addon apply simconnect-tcp
~/flightsim-on-linux/bin/flightsim-on-linux addon apply volanta

Run both with the simulator closed. The second one does two things.

It makes the add-ons prefix. A Wine server serves one prefix, and a program started next to the simulator joins the simulator's server. Volanta needs nothing from the simulator's memory, so it can leave. The add-ons prefix lives in ${XDG_DATA_HOME:-~/.local/share}/flightsim-on-linux/addons-prefix and has:

  • its own registry, copied once from the simulator's prefix (system.reg, user.reg, userdef.reg), and its own Wine server;
  • drive_c and the drive letters linked to the simulator prefix's, so installs, logins and settings are shared;
  • disable in .update-timestamp, so Wine never rewrites the windows folder the two prefixes share;
  • Wine's menu builder switched off, and the X11 driver, because Wine picks the driver for a whole prefix. The X11 driver is the one that took Volanta's icon to the KDE tray: on 30 October 2026 it opened logged in and sat in the tray.

The registry is a copy and nothing keeps it in step. A program you install in the simulator's prefix later isn't in the add-ons prefix's registry. If you make the prefix again with FSOL_ADDONS_PREFIX_RESET=1, which copies the registry again, whatever the add-ons wrote into the old registry is lost. apply never does that by itself: with the prefix there, it says so and leaves the registry alone. The command refuses while a Wine server holds either prefix.

It writes SimConnect.cfg. A program on another Wine server can't use the pipe SimConnect normally uses, so it reaches the simulator over TCP. simconnect-tcp moves the simulator's static IPv4 port from 500, which Linux doesn't let it open, to 5111. The file holds Protocol=IPv4, Address=127.0.0.1 and the port that SimConnect.xml declares, and sits in the add-ons prefix folder. The launch script starts Volanta from that folder, which is where its connector looks. If simconnect-tcp hasn't been applied, apply stops and prints the command, and so does check.

Volanta also gets Chromium options, --in-process-gpu --disable-gpu --disable-gpu-compositing. They keep Chromium's compositor inside the main process instead of a separate GPU process. Without them, on the test machine, the window in the simulator's container stayed white. In the add-ons prefix they draw under either driver, and the window turns white again if the DXVK overrides are missing, because Chromium then falls to Wine's own Direct3D. The prefix's Wine runner forces those overrides on.

With the GPU inside the main process, Chromium creates a Direct3D 11 device through DXVK, which takes your default GPU. On the test machine that meant 1,186 MiB on the RTX 4080 on 14 October 2026, so the test machine moved Volanta to its integrated Radeon with settings that belong to that machine. The add-on leaves them out. If you have one GPU, do nothing: Volanta runs on it.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut volanta

This writes an entry called "Volanta" in your application menu, with Volanta's own icon when 7z and magick are installed. Unlike most add-ons here, it doesn't need the simulator: it starts Volanta in the add-ons prefix, and with Volanta already open it says so and does nothing.

To have it start with the simulator:

~/flightsim-on-linux/bin/flightsim-on-linux addon watcher volanta

This writes a user service called flightsim-on-linux-volanta.service and switches it on. It looks for the simulator every 8 seconds. About 20 seconds after a new simulator appears, it opens Volanta with --minimized, once for that simulator and never when Volanta is already open. It never closes Volanta, which stays open after the simulator closes. Stopping the service doesn't close it either. A service is the way because exe.xml would start Volanta on the simulator's Wine server, which is what this add-on avoids.

To quit Volanta, right-click its tray icon and pick Quit. The menu also has Show Volanta and Reset Window Position. It needs a Proton FS2024 built on or after 2 November 2026: before that, the menu opened at most once, on the second right-click after Volanta started, and addon check volanta says whether your build has both fixes. If KDE lets X11 programs scale themselves, which ~/.config/kwinrc records as a Scale above 1 under [Xwayland], the menu opens away from the icon, up and to the left. On the test machine, at 125%, it opened about 740 points left of and 380 points above an icon in the bottom-right corner. KDE passes the click to Wine at the icon's position without converting it to Xwayland's coordinates: KDE bug 491582. Its items still work where the menu lands.

To keep the prefix from coming up broken when Volanta opens with the simulator, also run addon watcher addons-prefix. Its guide has the reason.

On 30 October 2026, at 20:20, Volanta in a second prefix, set up by the test machine's own scripts, connected to the real simulator. Earlier, on 14 October 2026, in the simulator's container, its connector log had Connected to Flight Simulator msfs24 and Sending AIRCRAFT_UPDATE for a 777F.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check volanta

It prints five lines, each starting with ok or FAIL, and changes nothing, so you can run it with the simulator open:

  • the add-ons prefix exists and has its own registry;
  • drive_c of the add-ons prefix is a link to the simulator prefix's;
  • .update-timestamp holds disable;
  • SimConnect.xml declares a port above 1023;
  • SimConnect.cfg points at that port.

When the prefix is missing, run addon apply volanta. When the fourth line fails, it prints flightsim-on-linux addon apply simconnect-tcp, which is the fix.

Known problems

  • At every start Volanta runs VolantaPlugin_x86.exe, the FSX and P3D connector, and it exits at once with 0xC0000135, a missing DLL. It doesn't affect MSFS 2024, and wasn't investigated.
  • The window is white if the DXVK overrides are missing. Start Volanta through the menu entry or the service, which go through the prefix's Wine runner.
  • Don't run one program in both prefixes at once. The two Wine servers share the folder but not the file locks or the mutexes.
  • A flight saved to your Volanta account was never checked.
  • Programs in this prefix see another set of processes, so a program that looks for the simulator by its process name won't find it unless the sentinel is open. Volanta finds the simulator through UserCfg.opt and SimConnect, so it isn't affected.

Undo

Take out the menu entry and the service:

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut volanta --remove
~/flightsim-on-linux/bin/flightsim-on-linux addon watcher volanta --off

addon undo volanta leaves the add-ons prefix and its SimConnect.cfg, because they hold Volanta's registry and other add-ons run there. It prints the rm -r command that deletes the prefix, to run with its programs closed. Volanta itself stays in drive_c. Uninstall it from Windows' own list in the simulator's prefix if you want it gone.
