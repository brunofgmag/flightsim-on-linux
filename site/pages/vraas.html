title: vRAAS description: How to install and run vRAAS in MSFS 2024 under Proton: the Contrail store download, the installer that fails with exit 82 when Contrail is open, the add-ons prefix and the sentinel it runs with, the service that starts it with the simulator, and the log lines that look like errors and are not. ---

vRAAS

Tested with vRAAS 1.3.9 on 15 October 2026, and in the add-ons prefix on 1 November 2026. The trouble is the installer, which fails with exit 82 while Contrail is open, and the program, which starts in the add-ons prefix with Direct3D 9 off, with the sentinel open.

Get it

vRAAS is made by LAND3 Simulations and sold through the Contrail store. Contrail is a store app: it downloads the installer for you and doesn't run it. The file on the test machine was LAND3-Simulations-vRAAS-MSFS-FS24-139-1788548786.exe, version 1.3.9, a Velopack installer. The price and the store's address weren't recorded.

Contrail puts the file in drive_c/users/steamuser/Downloads under the prefix that bin/flightsim-on-linux machine --json prints as prefix. Close Contrail before you go on. The ground rules explain why a store counts as a program that is open.

Install it

Close the simulator, Contrail and every other program in the prefix. Then give the installer to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install vraas "<prefix>/drive_c/users/steamuser/Downloads/<the vRAAS installer>.exe"

Replace <prefix> with the prefix path that machine --json printed. The command does two things the installer can't do for itself:

  • It refuses to start while the simulator runs or any program is open in the prefix, and names those programs. The script also looks for Contrail by itself, and stops with a message before it runs anything.
  • It runs the installer alone in the simulator's prefix, with Proton's Wine, and waits until the prefix is free again.

Exit 82 is what Contrail causes. With Contrail open, the installer's --veloapp-install step failed with exit 82 and error 5, access denied, the same denial the ground rules describe for any installer run next to another program. When the installer ends with 82, the command prints this explanation and keeps the code. Any other exit code is passed on unchanged. Close Contrail, empty the prefix, and run the command again.

Contrail itself needs its own fixes to run on Linux. They are not part of this page.

Make it run

Close the simulator, then:

~/flightsim-on-linux/bin/flightsim-on-linux addon apply simconnect-tcp
~/flightsim-on-linux/bin/flightsim-on-linux addon apply vraas

The second makes the add-ons prefix if it isn't there, writes its SimConnect.cfg, and then runs the check. vRAAS needs no Proton patch. It needs three things when it starts:

  • Direct3D 9 off for vRAAS. It is a WPF program on .NET 8, and the ground rules say why WPF programs get that setting. The launch script turns it off for vRAAS alone, in the environment of the program.
  • SimConnect.cfg next to the program. vRAAS looks for it in its own folder and in Documents, never in the folder it was started from. The launch script copies it to AppData/Local/LAND3.vRAAS/current at every start, because an update replaces that folder. In Documents the programs on the simulator's Wine server would read it too.
  • The sentinel. vRAAS starts SimConnect only after it sees a process called FlightSimulator2024.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut vraas

This writes an entry called "vRAAS" in your application menu, with vRAAS's own icon when 7z and magick are installed. The entry starts vRAAS in the add-ons prefix, and with vRAAS already open it says so and does nothing.

To have it start by itself:

~/flightsim-on-linux/bin/flightsim-on-linux addon watcher addons-prefix sentinel vraas

This switches on three user services. addons-prefix and sentinel have their own guides. flightsim-on-linux-vraas.service looks for the simulator every 8 seconds. About 20 seconds after a new simulator appears, it starts vRAAS with -autostart, once for that simulator and never when vRAAS is already open. When that simulator closes, it asks the vRAAS it started to end with SIGTERM and never kills it. A vRAAS you opened yourself stays open. A service is the way because exe.xml starts its programs with the simulator's environment, and that environment turns Direct3D 9 on, which a WPF program can't have.

On 15 October 2026, vRAAS started by the test machine's own earlier watcher connected to the simulator. Its log recorded CurrentAircraft:FNX_32X, the download of the aircraft's configuration, and "Starting vRAAS" at the moment the camera entered the cockpit. The voice warnings played. On 1 November 2026 it flew in the add-ons prefix, started by the test machine's own scripts. The scripts of this add-on are a port of those, and have run against a fake simulator only.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check vraas

It prints six lines, each starting with ok or FAIL, and changes nothing: vRAAS.exe is in the prefix, under AppData/Local/LAND3.vRAAS/current, then three lines about the add-ons prefix and two about its SimConnect.cfg. When the first fails, run the install command again. When the others fail, run addon apply vraas.

Known problems

  • vRAAS's own log repeats AudioSessionProbe.Query failed every 5 seconds, with a NotImplementedException in IAudioEndpointVolume.GetChannelCount. Wine's mmdevapi doesn't implement that method. The line is written at debug level, it comes to about 6 MB of log for a day of flying, and the voice warnings play regardless, so you can ignore it.
  • The installer fails with exit 82 while Contrail is open, as above.
  • Without the sentinel, vRAAS stops at Starting API completed and never reaches Initializing Simconnect.
  • Closed with taskkill without /f, a vRAAS with a connection open didn't close in 5 seconds. The service sends SIGTERM for that reason.

Undo

Take out the menu entry and the service:

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut vraas --remove
~/flightsim-on-linux/bin/flightsim-on-linux addon watcher vraas --off

addon undo vraas removes the SimConnect.cfg next to the program and leaves the add-ons prefix. Stopping the service leaves a running vRAAS alone. Leave the addons-prefix and sentinel services on if another add-on uses them.
