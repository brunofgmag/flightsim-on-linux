title: REX Atmos Core description: How to run REX Atmos Core in MSFS 2024 under Proton: the WebView2 policy value, the two Proton FS2024 fixes it needs (the window and the sliders), the menu entry that starts it inside the simulator's container, and what to expect. ---

REX Atmos Core

Tested with REX Atmos Core 8.1.2025.1210 on 27 October 2026. One registry value and two Proton FS2024 fixes make it work, and one command checks all three. It has to run inside the simulator's container.

Get it

REX Atmos Core comes from rexaxis.com and needs a serial. The installer is rexatmoscore_setup.msi, a Windows Installer package, version 8.1.2025.1210. Whether it is paid wasn't recorded.

Install it

Close the simulator and every program in its prefix first, and run nothing else while the installer works. The ground rules explain why. REX has no addon install script. It went into C:\REX Atmos Core of the simulator's prefix on 14 October 2026; which program ran the MSI wasn't recorded, and no installer problem was.

On the test machine REX activated on its first opening and wrote startup.json with the name of this computer, so the licence is tied to the machine.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply rex-atmos-core

Run it with the simulator closed. It changes one registry value and then runs the check. The value is weathercreator.exe, under HKCU\Software\Policies\Microsoft\Edge\WebView2\AdditionalBrowserArguments, and it holds --in-process-gpu --disable-gpu --disable-gpu-compositing --disable-software-rasterizer. It keeps any value that name held before, and addon undo puts it back.

REX's whole interface is a Blazor page inside a WebView2. Under Wine's Wayland driver, the WebView2 area belongs to a second process (msedgewebview2.exe), and stock Wine drops what that process draws. Two things have to hold for REX to show its window:

  • Proton FS2024 with win32u-cross-process-child-windows.patch, which makes Wine keep what the second process draws. On 15 October 2026, before this patch, REX opened, activated and said "Simulator Link: Active", but its window stayed empty. It has drawn since 17 October 2026.
  • WebView2 drawing in software, which the policy value does. The patch only helps a WebView2 that composes in software. A value named after a program replaces the * value for that program instead of adding to it, so it repeats all four options.

The sliders need a second fix. The Rayleigh, atmosphere depth, scattering height, phase function and particle sliders work by writing one pointer inside the simulator's code. The write goes through REX's own DLL, which writes into the simulator's memory from outside, and the page it lands on is one Wine reports as writable copy-on-write but Linux maps read-only (r-x). Windows copies the page on write. Wine's server used process_vm_writev, which Linux refuses on that page, and REX doesn't check the result. On 27 October 2026, without the fix, the sliders moved and only Overall Light Tuning changed the simulator; Rayleigh R, G and B, Atmosphere Depth, Scattering Height, Phase Function and the particle sliders did nothing, and REX reported no failure. Proton FS2024 has server-process-vm-write-falls-back-to-ptrace.patch, which writes that page with ptrace when process_vm_writev refuses it. With it, the sliders worked the same day.

The launch script also turns Direct3D 9 off for REX, as the test machine ran it. REX is a WPF program, and the ground rules say why WPF programs get that setting. Whether REX still needs it on Proton FS2024 wasn't measured. The script chooses nothing about which GPU REX uses.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut rex-atmos-core

This writes an entry called "REX Atmos Core" in your application menu, with REX's own icon when 7z and magick are installed. The entry starts REX inside the running simulator's container. With the simulator closed it tells you to start the simulator first, and with REX already open it says so and does nothing. REX has no watcher, so nothing starts it for you.

REX must stay on the simulator's Wine server. It writes into the simulator's memory, and a program on another Wine server can't do that.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check rex-atmos-core

It prints three lines, each starting with ok or FAIL, and changes nothing, so you can run it with the simulator open:

  • the Proton's fs2024-build.txt lists win32u-cross-process-child-windows.patch, and its win32u.so is the one the build recorded;
  • the same for server-process-vm-write-falls-back-to-ptrace.patch and the Proton's wineserver;
  • the WebView2 policy has a weathercreator.exe value with the four software options.

When one of the first two fails, rebuild Proton FS2024 with bin/flightsim-on-linux proton build. When the last one fails, run addon apply again.

Known problems

  • Without the wineserver fix, the sliders move and most never reach the simulator, and REX shows no error. The check catches it.
  • Why that page is r-x in Linux is unexplained. The guess, not measured, is an mprotect call made by the simulator's own protection code with a direct system call, outside Wine. Comparing /proc/<pid>/maps of the simulator just after its image loads with the same file at the main menu would tell.
  • The ptrace path answers an unmapped address with STATUS_ACCESS_DENIED where it used to answer STATUS_PARTIAL_COPY, as Wine did before it used process_vm_writev. kernelbase refuses free memory before it gets there, so programs that write through it don't see the change.
  • REX used to be used through a web page in a browser, because its window stayed empty. That route was retired on 17 October 2026, and nothing here needs it.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo rex-atmos-core
~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut rex-atmos-core --remove

The first puts the policy value back to what it was before apply, or removes it if it didn't exist. The second takes out the menu entry. Both Proton fixes stay, because other add-ons use them.
