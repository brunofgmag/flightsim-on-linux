Just Flight RJ Professional

Tested with the RJ Professional 0.1.6 on 16 October 2026. The installer needs no patch and no setting in the prefix. It has one trap, an environment variable that some tools put in everything they start, and addon install clears it for you.

Get it

The RJ Professional is an add-on from Just Flight. You download it from your Just Flight account, and the activation checks your purchase. This guide doesn't have the download page, so look in your account. On the test machine the download was Install_RJ_Professional_MSFS2024_0.1.6.zip, a zip with an InstallShield setup.exe inside.

Install it

Close the simulator and every other program of its prefix first, and run nothing else while the installer works. The ground rules explain why. Then give the zip to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install just-flight-rj-professional ~/Downloads/Install_RJ_Professional_MSFS2024_0.1.6.zip

Without the file name it only prints where to get the program. With it, the command refuses to start while the simulator runs or any program is open in the prefix, and names those programs. Then it unpacks the zip into a temporary folder, runs setup.exe in the simulator's prefix, and deletes the temporary folder when the installer ends, whatever the installer returns. It needs unzip for that. You can also unpack the zip yourself and give the command the setup.exe. On the test machine the installer found the Community folder by itself and ran the activation through WebView2.exe.

The environment variable that breaks the activation

The installer's own library for the account check, AccountX.dll, starts WebView2.exe with a web address and no folder in front of its name. That program sits in the support folder that InstallShield unpacks, which is the current folder. Windows looks in the current folder for a program started without a path, unless the environment variable NoDefaultCurrentDirectoryInExePath is set. Wine does the same. If the variable is set, the installer shows "Error Creating process" and then "Unable to confirm a valid purchase of the product".

Some tools set that variable for everything they start, and Wine inherits it. Claude Code, the AI coding tool, is one of them. On the test machine it was set in that tool's process and in what the tool started, and not in the desktop shell, the file manager or Steam, so the installer worked when opened from the desktop and failed when started from that tool. addon install removes the variable before it starts the installer, so you don't have to do anything. If you start the installer by hand from a terminal that has it, which env | grep NoDefault shows, put env -u NoDefaultCurrentDirectoryInExePath in front of the command. With the variable out of the way, the installer opened the Just Flight activation and installed.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply just-flight-rj-professional

This changes nothing, and then runs the check. Once it is installed, the RJ Professional needs nothing in the prefix. It was tested on Proton FS2024, and none of Proton FS2024's patches is known to matter for it. Stock Proton was not tried.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check just-flight-rj-professional

It prints one line, starting with ok or FAIL, and changes nothing, so you can run it with the simulator open. It wants Community/justflight-aircraft-rj to have a readable manifest.json, and the line gives the version. It fails if the folder is missing, if it is a link to a folder that is gone, or if the manifest can't be read. In that case run the install command again.

Known problems

  • None are open. The aircraft installed and activated on the test machine.
  • If the installer shows "Error Creating process", check the variable above before anything else.

Undo

addon undo just-flight-rj-professional has nothing to restore, because apply changed nothing. To remove the aircraft, use the RJ Professional's uninstaller as on Windows, with the simulator and the other programs of the prefix closed.
