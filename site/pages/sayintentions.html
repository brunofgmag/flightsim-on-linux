title: SayIntentions.AI description: How to install and run SayIntentions.AI in MSFS 2024 under Proton: the links watcher that keeps Wine's rmdir from emptying its packages, the WebView2 policy, .NET 4.8, fonts and voices, and the Proton FS2024 patches it relies on. ---

SayIntentions.AI

Tested with SayIntentions.AI Core 5.6.5.4 on 21 October 2026. It is a hard one: its Update Hub empties its own packages in Community under Wine unless a small service keeps them away, its window is a WebView2, and its helper program needs .NET Framework 4.8.

touches add-on files The fix copies WebView2Loader.dll beside SayIntentionsAI.exe, in the program's own folder. A copy that was already there is kept in compatdata/2537590/flightsim-on-linux-backup/sayintentions, and this puts it back, or removes the one the fix made:

~/flightsim-on-linux/bin/flightsim-on-linux addon undo sayintentions

Get it

SayIntentions.AI comes from www.SayIntentions.AI. The download is SayIntentionsAI_UpdateHub.exe, an Inno Setup installer for the Update Hub, and the Hub then downloads the components itself. The Core version the fixes were measured with is 5.6.5.4. On the test machine the Hub's local_manifest.json already lists 5.6.6.0 and Telemetry 1.0.2.0; whether 5.6.6.0 is installed or only listed wasn't confirmed.

Install it

The Hub installs what it downloaded during a flight only when the simulator closes, and it re-links every package in Community right after installing it. To do that it runs cmd.exe /C rmdir /S /Q "<link>", then mklink /D, then mklink /J, then copies the folder. On Windows rmdir /S on a link removes only the link. Under Wine it also empties the folder the link points to. On 14 October 2026 that made every opening of the Hub download the 610 MB of SimObjects Core and SkyOps again, and the packages were never in place while the simulator was open. A link made by Wine looks, from Linux, like an empty folder with the extended attribute user.WINEREPARSE. If the entry is removed from Linux first, the Hub's rmdir finds nothing to follow, and mklink makes the link again with its contents in place. That is what the links watcher does.

The order:

  1. Close the simulator and every other program in the prefix. The ground rules explain why installers run alone.
  2. Make sure the prefix has .NET Framework 4.8. SayIntentions 5.6.5.4 brought a helper, si_telemetry.exe, that cannot run on wine-mono; without 4.8 the interface stays on its loading screen. addon apply dotnet48 installs it; its guide and Installing add-ons explain what it does and why.
  3. Switch the links watcher on with addon watcher sayintentions, under "Start it". Leave it on.
  4. Give the installer to the CLI: 
    ~/flightsim-on-linux/bin/flightsim-on-linux addon install sayintentions ~/Downloads/SayIntentionsAI_UpdateHub.exe
    It runs the installer in the simulator's prefix with Direct3D 9 off for that one program, which the Hub needs. It refuses to start while the simulator runs or any program is open in the prefix, and it refuses while the links watcher is not running.
  5. Let the Hub download and install its components, then close it. The watcher keeps the links away while it runs and gives them back when it ends.
  6. Run addon apply sayintentions.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply sayintentions

Close the simulator first. The command writes these settings with one regedit import, keeps what each one replaced, and copies one file:

  • The WebView2 policy. The value SayIntentionsAI.exe under HKCU\Software\Policies\Microsoft\Edge\WebView2\AdditionalBrowserArguments gets the four software options: --in-process-gpu --disable-gpu --disable-gpu-compositing --disable-software-rasterizer. Without them the browser runs a separate GPU process, the Wayland driver loses what it draws, and the middle of the window stays grey. The program's own entry replaces the * entry instead of adding to it, so it repeats all four. An environment variable doesn't work here: the program passes its own arguments to WebView2 and they win.
  • Windows 7 for the browser. msedgewebview2.exe gets Version=win7 under HKCU\Software\Wine\AppDefaults. The prefix used to test the WebView2 fixes had it. Why the browser needs it isn't recorded.
  • The native .NET for the helper. si_telemetry.exe gets mscoree=native under its own DllOverrides, so it runs on the prefix's .NET Framework 4.8, and only when 4.8 is there. On wine-mono it dies at start with TypeLoadException, because the mono has no CertificateRequest class. On 4.8 it runs further and then fails in its certificate, which is not an error that matters (see "Known problems").
  • The WebView2 loader. It copies runtimes\win-x64\native\WebView2Loader.dll beside SayIntentionsAI.exe. wine-mono looks beside the program and doesn't look in runtimes, so without the copy the program warns "SayIntentions ... failed to load" and no browser process starts. With it, six msedgewebview2.exe processes started. An update of SayIntentions can delete the copy; run apply again.
  • Six fonts. Tahoma, Tahoma Bold, Marlett, Symbol, Webdings and Wingdings in HKLM\Software\Microsoft\Windows NT\CurrentVersion\Fonts. Proton's wine.inf registers them, and a prefix whose links were dangling during a run can lose them. Without Tahoma the WebView2 browser asks DirectWrite for it, doesn't find it, falls back to a font that leads back to Tahoma, and overflows its 8 MB stack. SayIntentions then warns that it failed to load; it did in all three openings tried on 18 October 2026. With the six back, a DirectWrite test found Tahoma and the program logged WebView2 ready on 18 October 2026.

Not part of the command: the font substitutions for Segoe UI, Consolas and a few others, which keep the text from being drawn in Times New Roman. bin/flightsim-on-linux doctor offers them.

It also needs four things from the Proton FS2024 build and one app from Steam:

  • win32u-cross-process-child-windows.patch: the WebView2 part of the window comes from a second process, and stock Wine dropped what it drew.
  • winewayland-opaque-xrgb.patch: the window no longer goes black on some outputs under KWin 6.8, which read the fourth byte of the pixel as transparency.
  • The audio session notification in Proton's mmdevapi.dll, which the Fenix overlay patch in the build adds. Without it the program closes a few seconds after it speaks, because its audio library gets "not implemented" when it unregisters a session notification and a finalizer turns that into a crash. The check looks at the build record.
  • ntdll-heap-bounded-free-list-scan.patch, from 30 October 2026. See "Known problems": it is expected to help, and it hasn't been seen in flight.
  • The free Steam app Proton Voice Files, app 3086180, 75 MB. SayIntentions speaks through the SAPI voices Proton registers, and they point at a model file Proton doesn't ship. Without the app the program warns "ATIS audio can not play on this computer". Inside the simulator's container the other two variables the voices need come from the game's environment, and flightsim-on-linux run adds PROTON_VOICE_FILES. Started with protontricks-launch instead, the warning came back on 14 October 2026.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut sayintentions

This writes an entry called "SayIntentions.AI" in your application menu. With the simulator closed it tells you to start the simulator first: the program runs inside the simulator's container. With the simulator running, it removes the SayIntentions links from Community (and only those: a link that points anywhere else, like GSX's, stays), then opens the Update Hub in the container with Direct3D 9 off. If the Hub is already open it says so and does nothing. Never open the Hub with the simulator running except through this entry. On 14 October 2026 a Hub opened directly with the simulator running left the four packages with zero files; opened through the launcher, 668, 1,129, 10 and 12 files stayed. The entry needs getfattr, from the attr package, to find the links.

~/flightsim-on-linux/bin/flightsim-on-linux addon watcher sayintentions

This writes the user service flightsim-on-linux-sayintentions.service and switches it on. It is a watcher of the loop kind, described in Shortcuts and watchers: it starts no program with the simulator. It runs the add-on's links-watcher script for as long as the service lives and runs it again if it fails. Stopping the service stops the script, and the script gives the links back first.

Every second it looks. While the Hub runs and the simulator doesn't, it saves the extended attribute of each SayIntentions link in your backup folder (compatdata/2537590/flightsim-on-linux-backup/sayintentions/links) and removes the entry. When the Hub is gone it gives back every link the Hub didn't make again, with the same attribute. It needs getfattr and setfattr (the attr package) and iconv. If you stop the service while the Hub is open, it gives the links back first. On the test machine, with stand-in processes for the Hub and the simulator on 14 October 2026, the four links left within 2 seconds and came back with identical attributes; with a simulator process present they stayed; and a copy of the watcher without the simulator test removed them.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check sayintentions

It prints ten lines, each starting with ok or FAIL, and changes nothing, so you can run it with the simulator open:

  • the policy value for SayIntentionsAI.exe holds the four options;
  • msedgewebview2.exe has Version=win7;
  • the prefix has .NET Framework 4.8 and si_telemetry.exe has mscoree=native;
  • WebView2Loader.dll beside the program is the one in runtimes;
  • the six fonts are in the registry;
  • Proton has the child-window patch, the opaque pixel patch and the heap patch, and its mmdevapi.dll is the one the build recorded, with the overlay patch in the record;
  • the Steam app Proton Voice Files is in one of your libraries.

The check doesn't look at the links watcher; systemctl --user status flightsim-on-linux-sayintentions.service does.

Known problems

  • One opening in three hangs before the WebView2 comes up. End the program and open it again.
  • The heap patch is expected, not seen. With the A321 and SayIntentions traffic, the process heap on the test machine held about 40,000 free blocks of up to 1,504 bytes in one list, and every 1,520-byte request walked all of them under the heap lock, which stopped the simulator for 50 to 185 ms once a second. The patch moves on to the next list after 64 blocks that are too small, and lets blocks up to 2 KiB reach the low-fragmentation heap after 2,048 allocations. The stalls should go away with SayIntentions open. Traffic is the likely trigger, not the proven one, and nobody has flown with this build and the Hub open yet, so this is what to expect, not what was seen.
  • si_telemetry.exe crashes with ArgumentException: The provided key does not match the public key for this certificate and the program opens it again every 20 seconds. This is harmless as far as the test machine shows: ATC worked normally with it down, and the cause, probably in Wine's crypt32 or bcrypt, wasn't measured.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut sayintentions --remove
~/flightsim-on-linux/bin/flightsim-on-linux addon undo sayintentions
~/flightsim-on-linux/bin/flightsim-on-linux addon watcher sayintentions --off

The first removes the menu entry. undo puts the registry settings back to what they were before apply (a policy text that was there is written again, and a value that wasn't there is deleted) and takes out the copy of WebView2Loader.dll, or puts back the one that was there. The last one switches off the links watcher and deletes its unit file. undo leaves the Update Hub, SayIntentions and its packages alone.
