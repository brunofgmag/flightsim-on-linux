title: Active Sky FS description: How to run Active Sky FS in MSFS 2024 under Proton: the installer and its connector, the Calibri to Carlito replacement and the Proton fix behind it, the add-ons prefix and the sentinel that keep it off the simulator's Wine server, why it is closed and never killed, and the licence dialog that ignores the mouse. ---

Active Sky FS

Tested with Active Sky FS 1.0.9720.20096 on 15 October 2026, and in the add-ons prefix on 1 November 2026. It takes a few steps rather than one command: a font replacement that needs a Proton fix, a second Wine prefix with a stand-in for the simulator's process, and a licence dialog you have to drive with the keyboard.

Get it

Active Sky FS is a paid add-on from HiFi, sold at hifisimtech.com. You need a login and a licence key. The installer is AS_FS_Install.exe, an Inno Setup installer.

Install it

Close the simulator and every program in its prefix first, and run nothing else while the installer works. The ground rules explain why. Active Sky has no addon install script, so run the installer the way the ground rules show:

protontricks-launch --no-term --appid 2537590 ~/Downloads/AS_FS_Install.exe

On the test machine the installer went into C:\Program Files\HiFi\AS_FS of the simulator's prefix. Which program ran it on 14 October 2026 wasn't recorded, and no installer problem was.

That folder also holds AS_FSConnectorInstall.exe. The connector puts three things in place: the asfs package in Community, an AddonFolder with ActiveSkyUtils.exe under AppData\Roaming\HiFi\AS_FS, and an ActiveSky Utils entry in exe.xml. Whether the main installer starts the connector for you wasn't recorded. If Community has no asfs folder afterwards, run the connector the same way, from the same folder.

Active Sky does not talk to the simulator by itself. ActiveSky Utils hands the simulator's data to AS_FS.exe through a named pipe, and a script in the asfs package asks Active Sky's local API for the weather and applies it. The connector's exe.xml entry would start Utils on the simulator's Wine server, out of the pipe's reach, so this add-on turns that entry off and a watcher starts Utils next to Active Sky.

Install Active Sky before you run addon apply active-sky. The add-ons prefix holds a copy of the registry, and a program you install later isn't in it. Its guide says how to copy it again.

Make it run

Install the Carlito font first. On Arch that is the ttf-carlito package; other distributions package Carlito under their own name. Then close the simulator and run:

~/flightsim-on-linux/bin/flightsim-on-linux addon apply simconnect-tcp
~/flightsim-on-linux/bin/flightsim-on-linux addon apply active-sky

The second refuses when no Carlito font is installed, and writes nothing then. Otherwise it does four things:

  • It makes the add-ons prefix if it isn't there, and writes its SimConnect.cfg.
  • It copies that file next to ActiveSkyUtils.exe. If the connector hasn't put Utils in place yet, it says so. Run it again afterwards.
  • It sets two values in HKCU\Software\Wine\Fonts\Replacements of the add-ons prefix: Calibri and Calibri Medium, both to Carlito.
  • It sets Disabled to True on the ActiveSky Utils entry of exe.xml, and remembers that it did. If there is no such entry yet, it says so. Run it again after the connector writes one.

The registry values are only half of it. Active Sky asks GDI+ for the fonts Tahoma, Microsoft Sans Serif and Calibri. Wine's GDI+ finds a family only when the font's full name equals its family name, and Carlito's full name is "Carlito Regular", so on 15 October 2026 Active Sky stopped at its own error screen, The requested FontFamily could not be found. Proton FS2024 carries gdiplus-font-family-after-substitution.patch, the upstream Wine fix (commit e6e9d7627c, in Wine 11.17): GDI+ asks GDI which family it chose after the substitution, so the replacement works. The first workaround, copying Carlito into the prefix's Fonts folder under the name Calibri, was retired on 18 October 2026.

On 18 October 2026, with the fix and the registry values, a font test program run in the simulator's container got GDI+ status 0 for Calibri. With the Calibri value removed it got 14, FontFamilyNotFound, and with the value back it got 0 again. Whether Active Sky's own screens draw the same was not checked.

On 1 November 2026 the test machine's own scripts ran Active Sky and Utils in the add-ons prefix, and the flight that day had its weather. The scripts of this add-on are a port of those, and have run against a fake simulator only.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon watcher addons-prefix sentinel active-sky
~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut active-sky

The first switches on three user services. addons-prefix keeps the add-ons prefix up from your login. sentinel keeps a stand-in called FlightSimulator2024.exe open there while the simulator runs, because Utils closes when it can't find that process. active-sky keeps ActiveSky Utils open for as long as the sentinel is: if Utils dies, the next look, within 8 seconds, opens it again. With Active Sky open, Active Sky gets there first and runs Utils in AddonFolder, so apply and the menu entry copy SimConnect.cfg there. When the simulator closes, the sentinel goes and Utils closes by itself.

The second writes an entry called "Active Sky" in your application menu, with Active Sky's own icon when 7z and magick are installed, and a "Close Active Sky" action. The entry starts Active Sky in the add-ons prefix, with or without the simulator, and with Active Sky already open it says so and does nothing. You start Active Sky yourself, and it stays open when the simulator closes.

The "Close Active Sky" action asks Active Sky's window to close, the way the close button does, and never kills the process. That matters on this machine:

  • On 15 October 2026 three runs of Active Sky in a row, each started after the previous one was killed with pkill, logged MSFS connection established! and changed nothing in the simulator. The weather API answered 503 with "message": "No sim connection", and a Mono trace showed a named-pipe connect timing out 43 times in two minutes. Closing Active Sky through its window and reopening it, with the same Utils still running, left the API at 200 and the simulator's script running.
  • On 30 October 2026, after a pkill, the next openings stopped at "Existing Session": HiFi's server still held the old session, and it was still there eight minutes later. After a taskkill without /f, the next opening logged in at once.

If Active Sky stays after the request, the action says so and leaves it. Close it from its own window.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check active-sky

It prints twelve lines, each starting with ok or FAIL, and changes nothing, so you can run it with the simulator open:

  • three about the add-ons prefix, and two about its SimConnect.cfg;
  • the SimConnect.cfg next to ActiveSky Utils matches that one, or Utils isn't installed yet;
  • the ActiveSky Utils entry of exe.xml is off or absent;
  • the Proton was built with gdiplus-font-family-after-substitution.patch, and its gdiplus.dll is the one the build recorded;
  • a Carlito font is installed;
  • Calibri and Calibri Medium are each replaced by Carlito in the add-ons prefix, one line each;
  • the weather API answers 200. This line looks only when Active Sky and the simulator both run. With Active Sky closed it says so and passes.

The API is http://127.0.0.1:19285/ActiveSky/API/GetWeatherInfoJson, and you can ask it yourself with curl -s. It lists the weather layers when Active Sky is feeding the simulator, and answers 503 when it isn't. Read the API and not Active Sky's log: the log said "MSFS connection established!" in the three runs above that changed nothing.

When the Proton line fails, rebuild Proton FS2024 with bin/flightsim-on-linux proton build. When the font lines, the exe.xml line or the line about the copy of SimConnect.cfg fail, run addon apply again.

Known problems

  • The OK button of the licence dialog, "Active Sky FS License", ignores the mouse, and so does the X of that window. Press Tab until OK is selected, then Space. On 15 October 2026 that went through. A window list taken inside the container showed the dialog visible and enabled, the Login window behind it disabled, and no other modal window. Why the click doesn't reach this one dialog, while it reaches the Login window and the main window, wasn't measured.
  • A killed Active Sky leaves the weather API at 503 and the account on "Existing Session", as above. To get the weather back, close Active Sky and close ActiveSky Utils (pkill -f 'ActiveSkyUtils[.]exe'). With the sentinel open, the watcher opens Utils again within 8 seconds. On 15 October 2026, reopening only Utils took the API to 200 in 18 seconds.
  • Not errors: the log says Could not find file ...\Weather\tempsfc.bin four times for every download, then "Download failed, retrying..." and "Download complete". Active Sky's own processing of the GFS data runs a cmd pipe through wgrib2 and findstr that doesn't write that file, so it falls back to the download HiFi's servers already processed, and the weather arrives all the same. Why the pipe fails wasn't measured.
  • Without the sentinel, ActiveSkyUtils.exe closes within seconds, because it looks for a process called FlightSimulator2024 and can't see the simulator's from this Wine server.
  • Active Sky stays on "Connection: Waiting for Simulator" with the simulator running, and AS_FS_SimConnectionLog.txt in AddonFolder repeats Failed to connect every 10 seconds: that Utils has no SimConnect.cfg. It stays up, so nothing looks wrong from outside, and the watcher leaves it alone. On 1 November 2026, on the test machine, a Utils without the file never connected in the 48 seconds it ran. The next one, with the file, logged Connected to the sim within 15 seconds. addon apply active-sky copies the file, and closing Utils with pkill -f 'ActiveSkyUtils[.]exe' brings up one that reads it.
  • An Active Sky update can turn the exe.xml entry back on. The simulator then opens a second Utils on its own Wine server, out of reach of Active Sky's pipe. addon check fails on that line, and addon apply active-sky turns it off again.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo active-sky
~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut active-sky --remove
~/flightsim-on-linux/bin/flightsim-on-linux addon watcher active-sky --off

The first removes the two Replacements values from the add-ons prefix and the SimConnect.cfg next to ActiveSky Utils, and turns the ActiveSky Utils entry of exe.xml back on if apply turned it off. It leaves the Carlito font installed. The second takes out the menu entry and the third the service. Leave the addons-prefix and sentinel services on if another add-on uses them.
