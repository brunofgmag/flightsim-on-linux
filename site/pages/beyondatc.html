BeyondATC

BeyondATC 1.8.23 EA was opened on the test machine on 30 October 2026, in a test prefix and not through this add-on's launch script. The launch behaviour below was measured with 1.8.22 EA on 14 October 2026. It needs nothing in the prefix and no Proton fix.

Get it

BeyondATC is made by Skirmish Mode Games and comes from beyondatc.net. The version on the test machine is 1.8.23 EA (early access), installed with an Inno Setup installer into C:\BeyondATC. The installer's file name wasn't recorded.

Install it

Close the simulator and every program in its prefix first, and run nothing else while the installer works. The ground rules explain why. BeyondATC has no addon install script. On the test machine it was installed into the simulator's prefix with protontricks-launch, and no installer problem was recorded.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply beyondatc

This changes nothing, and then runs the check. BeyondATC needs no Proton patch and no registry value. It has to start inside the simulator's container: the parts of it that control the jetways import ReadProcessMemory, WriteProcessMemory and CreateRemoteThread, read from the decompiled program on 30 October 2026, so they act on the simulator's process.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut beyondatc

This writes an entry called "BeyondATC" in your application menu, with BeyondATC's own icon when 7z and magick are installed. The entry starts BeyondATC inside the running simulator's container. With the simulator closed it tells you to start the simulator first, and with BeyondATC already open it says so and does nothing. There is no watcher and no close action.

The launch script sets nothing about graphics. BeyondATC is a Unity program, and Unity picks its own renderer. On 14 October 2026, with 1.8.22 EA started with nothing set, it drew with Vulkan on the RTX 4080 and held 130 to 134 MiB of that card.

Programs out of the main GPU

This is an option, and the add-on doesn't do it. It helps when you want BeyondATC's drawing out of the video memory of the GPU the simulator uses, and you accept that the drawing moves to the CPU. On the test machine the simulator needed that memory.

The launcher the test machine used passed three things to BeyondATC, through the simulator's container:

~/flightsim-on-linux/bin/flightsim-on-linux run \
  __EGL_VENDOR_LIBRARY_FILENAMES=/usr/lib/pressure-vessel/overrides/share/glvnd/egl_vendor.d/50_mesa.json \
  LIBGL_ALWAYS_SOFTWARE=1 \
  'C:\BeyondATC\BeyondATC.exe' -force-glcore

The first path is inside the Steam Linux Runtime container, not on your disk. The test machine read it from the simulator's process environment. -force-glcore makes Unity use OpenGL, LIBGL_ALWAYS_SOFTWARE=1 makes Mesa draw it on the CPU, and the first variable keeps the EGL loader on Mesa instead of the NVIDIA driver.

What the test machine measured on 14 October 2026 with 1.8.22 EA, by reading the game's Player.log and nvidia-smi:

What it was started withResult
nothingVulkan on the RTX 4080, 130 to 134 MiB of its memory.
the Vulkan loader limited to the integrated RadeonDies within seconds with error 7: importing the supplied dmabufs failed.
the software Vulkan driver (lavapipe)Unity refuses it: it lists the device as type 4, a CPU, and says Could not select a physical device. It fell back to OpenGL on the RTX, 116 MiB.
the three settings aboveOpenGL 4.5 on llvmpipe (LLVM 23.1.1, 256 bits), off the RTX. It cost 19 to 35% of one CPU core, measured with the program idle at the menu.

This guide can't say which renderer your BeyondATC uses when the menu entry starts it. The newest Player.log on the test machine, from 30 October 2026, says Renderer: NVIDIA GeForce RTX 4080, although the launcher of that time set software OpenGL. The most likely reason is that this log comes from the test in the add-ons prefix, outside the launcher, but that wasn't confirmed. Opening BeyondATC through the launcher with the simulator running and reading that line would settle it. Read the line on your machine before you rely on this option: the file is drive_c/users/steamuser/AppData/LocalLow/Skirmish Mode Games, Inc/BeyondATC/Player.log in the prefix.

The CPU number depends on your CPU, so measure it with BeyondATC open: ps -o %cpu= -p $(pgrep -f '^C:.*BeyondATC[.]exe').

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check beyondatc

It prints one line, ok or FAIL, and changes nothing: BeyondATC.exe is in C:\BeyondATC. When it fails, run the installer again.

Known problems

  • On the test machine, choosing the integrated Radeon kills BeyondATC with error 7: importing the supplied dmabufs failed. KWin composes on the RTX and doesn't import a buffer the other GPU drew, and Wine's Wayland driver loses the connection. Volanta escapes it because Chromium hands over its window through shared memory when its compositor is off; Unity has no such option.
  • Unity rejects lavapipe, as in the table.
  • On 14 October 2026, with the first run still on the RTX, BeyondATC stopped answering when SayIntentions opened, and its process was gone between 10:03:55 and 10:04:33, with no dump and no last line in Player.log. It didn't happen again: alone it stayed up, and on the software OpenGL run it ran with SayIntentions to the end. With one occurrence there is nothing to measure.

Undo

addon undo beyondatc has nothing to restore, because apply changed nothing. Take out the menu entry with:

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut beyondatc --remove
