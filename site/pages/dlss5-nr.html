DLSS 5 Neural Rendering

Tested on 20 October 2026 with an RTX 4080 and driver 615.78.08, using commit 5d493c9 of a fork of addon-dlssnr-linux and the 310.8.0 model. This is a ReShade add-on that runs NVIDIA's model over the simulator's own DLSS output. It costs a lot of frame rate.

touches add-on files The model is not in this project, and this project doesn't host it. It is NVIDIA's nvngx_dlssnr.dll, and the RTX 40 build below is a copy that the community modified, without a signature. NVIDIA doesn't publish it. Decide for yourself whether you want to run it.

There is no addon command for this one. You build two files, download a third and copy all three, so addon list doesn't show it and addon check can't prove it. The check is the log, further down.

What you need

  • An NVIDIA RTX 40 or RTX 50 card and driver 610 or newer. Only an RTX 4080 was tested here.
  • ReShade in the simulator's folder.
  • DLSS turned on in the simulator's graphics settings. Without it the add-on does nothing.

The test machine runs this on Proton FS2024 with no launch option for it. The add-on's own instructions ask for PROTON_FORCE_NVAPI=1 and a dxgi override on other Protons. Neither is set here, and the dxgi one isn't needed for the reason the ReShade guide gives.

Build the add-on

Use the fork, not the original project's releases. The releases have no model resolution setting, follow the wrong one of the simulator's two DLSS features, and hook DLSS in the wrong order next to the Glass Cockpit DLSS Fix.

git clone -b feat/model-scale https://github.com/brunofgmag/addon-dlssnr-linux
cd addon-dlssnr-linux
bash install-deps.sh
bash build.sh

install-deps.sh uses sudo for clang and LLD. It also puts the Windows SDK in ~/.xwin, a shader compiler in ~/.local/dxc and RenoDX in ~/projects/renodx. The SDK comes through xwin, and the script accepts Microsoft's licence for you, so read it first if that matters to you. The SDK takes a few hundred MB.

build.sh writes dlssnr-linux.addon64 and nvngx.dll_nrfwd.dll to build/.

Get the model

This is the build that runs on an RTX 40 card, from the release dlssnr-310.8.0-RTX40 of RankFTW/rhi-repo.

curl -fLO https://github.com/RankFTW/rhi-repo/releases/download/dlssnr-310.8.0-RTX40/nvngx_dlssnr_310.8.0-RTX40.zip
unzip nvngx_dlssnr_310.8.0-RTX40.zip
sha256sum nvngx_dlssnr.dll

The sum must be 4b8d19bc3eff58a084f5eca7489c921501c203450169fb82ff4f649a4482ba05. Don't guess with another model: the add-on's author saw a mismatched one report success on every frame and then crash the game minutes later. An RTX 50 card uses the unmodified model the add-on's README names, which wasn't tried here.

Install it

Close the simulator first. Run this from the folder of the fork, with the model's folder in place of /path/to/model.

SIM=$(~/flightsim-on-linux/bin/flightsim-on-linux machine --json | python3 -c 'import json,sys; print(json.load(sys.stdin)["sim_install"])')
cp build/dlssnr-linux.addon64 build/nvngx.dll_nrfwd.dll /path/to/model/nvngx_dlssnr.dll "$SIM/"

Use it

Start a flight with DLSS on and press Home to open ReShade. In the Add-ons tab the add-on is called DLSSNR Linux. F10 turns the effect on and off, and so does the "Enable Neural Rendering (F10)" box.

"Model resolution" runs the network smaller, for more frame rate. It and the other model settings only take effect after the "Apply model settings" button.

On the test machine, in 4K with DLSS Performance and no frame generation, at Copenhagen with the Orbx scenery:

At 0.50 the engine cowlings already look flat, and at 0.35 they get a bright halo on the edge. With frame generation and a limit of 33 frames per second, 66 on screen, 0.60 held the 66 while turning the camera, with short drops to 62, and 0.75 fell to 54.

Check it

Read ReShade.log in the simulator's folder after the flight has loaded.

grep -E 'nr-fwd: model|hooked 5 NGX exports' "$SIM/ReShade.log"

The first line to look for starts with nr-fwd: model nvngx_dlssnr.dll and gives the model's version and sha256. The second is hooked 5 NGX exports on _nvngx.dll, and with the Glass Cockpit DLSS Fix installed it ends in , over the Glass Cockpit DLSS Fix.

The add-on warns that the RTX 40 model isn't the build it was tested with. That warning is expected. So is WARNING DLSS evaluate hook was changed by another mod in the Glass Cockpit DLSS Fix's log: the calls still reach it.

With the Glass Cockpit DLSS Fix

Both add-ons hook the same DLSS call, and this one has to run last. If the fix's .addon64 is in the same folder, the add-on waits up to 60 seconds for the fix to hook, then hooks over it. In the other order the screens got cloud-like patches and shimmering grain. The wait looks for that file name, so the fix's standalone dxgi.dll version doesn't count.

Known problems

  • At 0.50 and below, raising the model's intensity settings doesn't bring back the shape lost on the engine cowlings.
  • A newer model, 310.9.16 from openNR, ran about 14% faster on the same card, but on a later build of the add-on that isn't published, so it isn't part of this guide.

Undo

With the simulator closed:

rm "$SIM/dlssnr-linux.addon64" "$SIM/nvngx.dll_nrfwd.dll" "$SIM/nvngx_dlssnr.dll"

ReShade and the Glass Cockpit DLSS Fix stay. $SIM is the folder from the install step.
