title: MFG Unlocker description: How to run dashdogy's MFG Unlocker 1.7.0 in MSFS 2024 under Proton FS2024 on an RTX 40 card: the pinned download, the seven byte patches Wine needs, the four launch options and the fixed mode. ---

MFG Unlocker

Tested with MFG Unlocker 1.7.0 on 5 November 2026, on an RTX 4080 with Proton FS2024 and ReShade 6.8.0 as dxgi.dll. It adds multi frame generation, 3x to 6x, to the simulator's DLSS frame generation on an RTX 40 card, with a menu that opens on Backspace. Under Wine the official file needs seven small patches before the menu works, and the simulator needs the mod in fixed mode before it generates a single frame. This add-on does both.

touches add-on files The install patches a copy of the mod's own DLL, 123 bytes of it, and writes the copy as version.dll in the simulator's folder. apply edits the mod's own config file, RTXMFG-Universal.json, in the same folder. The first time, it keeps the original in compatdata/2537590/flightsim-on-linux-backup/mfg-unlocker, and this puts it back and removes the DLL:

~/flightsim-on-linux/bin/flightsim-on-linux addon undo mfg-unlocker

Get it

MFG Unlocker is free and MIT-licensed (copyright 2026 Michael Robles), from dashdogy's releases page on GitHub. The file is MFGUnlocker-v1.7.0.zip of release 1.7.0. You don't need to download it yourself: the install command does.

This repository ships no DLL. It holds the list of bytes to change, in addons/mfg-unlocker/parts/patches.json, and the install applies that list to the official file.

  • The zip has sha256 5bd19d03288e1ece1d0bb2030ac072b36758045028da192044dcaad73fd901dd.
  • MFGUnlocker.dll inside it has sha256 e6b6e6b70a6ed3af839c9647a32fc22660ae6b2d655062c5c072246c91fc10c7.
  • The patched file has sha256 a610fc756ce93e04be6719a9077e85eca3c3121fdad8a4cf9a9a7cf3d3dce5cf.

Install it

Install ReShade first: every patch below was measured with it, and this guide has not been tried without it. The simulator has to be closed.

~/flightsim-on-linux/bin/flightsim-on-linux addon install mfg-unlocker

The command downloads https://github.com/dashdogy/MFG-Unlocker/releases/download/v1.7.0/MFGUnlocker-v1.7.0.zip with curl (the release is tagged v1.7.0), checks the zip's sha256 and keeps it in ~/.cache/flightsim-on-linux/downloads. Then it reads MFGUnlocker.dll from the zip and checks its sha256. It checks that every byte it is about to change is the one the list expects, changes them, checks the sha256 of the result and only then writes it as version.dll beside FlightSimulator2024.exe. Any other file stops it before anything is written. The hashes are pinned because this is the release the patches were measured with. A newer release needs its patch sites found again.

If you already downloaded the zip, give it to the command: addon install mfg-unlocker /path/to/MFGUnlocker-v1.7.0.zip. It must be the same release.

If the simulator's folder already has a version.dll that is not the patched one, the command names it and stops. Another mod uses that name, and nothing here overwrites it.

Make it run

The order matters, because the mod writes its config file the first time it runs and apply edits that file:

  1. Install the add-on, as above.
  2. Add the launch options below in Steam.
  3. Start the simulator once and close it. The first start compiles shaders and stutters.
  4. Run ~/flightsim-on-linux/bin/flightsim-on-linux addon apply mfg-unlocker.

The seven patches

The official file is built for Windows, and under Wine seven things in it go wrong. The install changes 123 bytes in 18 places, and every change removes a jump, swaps a byte or rewrites text of the same length. The other checks in each function stay.

  • Menu import. The mod asks ntdll for RtlIsThreadWithinLoaderCallout. Wine doesn't have it, so the mod believes it is always inside the loader. Frame generation still works, but the menu and the swap chain hooks never install: the log has MFG_PROXY_UI factory gateway first call lines and never state=active. The patch renames the import to RtlDllShutdownInProgress, which Wine exports with the same signature.
  • Shaders. The mod compiles its DLSS 5 shaders when it runs, with Wine's compiler, which has no isfinite for shader model 4 and 5. The log has E5017: Aborting due to not yet implemented feature: SM4 isfinite expression, then DLSS 5 setup refused: step=compute pipeline, and the DLSS 5 tab says "Waiting for DLSS". The patch rewrites the six isfinite calls in the two embedded shaders as abs(x)<3e38 comparisons of the same length.
  • Provider protection. The mod makes a memory page writable and then checks that it says PAGE_READWRITE. Wine says PAGE_WRITECOPY for the pages of a loaded DLL. The log has DLSS 5 direct provider open failed: result=0xBAD00002, and the tab says "GPU or provider unsupported". The patch changes one byte, from 4 to 8, so the check accepts PAGE_WRITECOPY.
  • The factory's module path. The simulator imports CreateDXGIFactory from dxgi.dll, and the mod only hooks that import when the module is C:\windows\system32\dxgi.dll. Here it is ReShade's. The log has application graphics import publication unavailable and mainGraphicsImports=0. The patch removes the jump after the path comparison.
  • The adapter-parent route. The simulator builds its swap chain on the factory it gets from adapter->GetParent, and ReShade's adapter proxy answers with ReShade's own factory, so the mod never sees the swap chain: the log has factory gateway first call and never swapchain creation. The mod has a route for exactly this, but it gives up without a log line unless the adapter belongs to the system dxgi.dll. The patch removes the seven jumps of those owner checks.
  • The module handle. That route also asks GetModuleHandleW(L"dxgi.dll") for the system copy. Under Wine the call returns ReShade's after any other module lookup. The patch removes the jump after that comparison. With it and the one before, the log has adapter-parent entry armed, then swapchain creation 1 and renderer registered.
  • Textures with mips. For the DLSS 5 tab's Before and After upscaling, the mod takes only textures with one mip, and the simulator hands DLSS its output and depth with the whole mip chain. The tab stays at "DLSS inputs unavailable" and the log has DLSS 5 inputs refused lines that end in mips=12 for the output and mips=11 for the depth. The patch removes the jump after the mip count check.

The launch options

Steam keeps the launch options of the simulator in localconfig.vdf and rewrites that file, so nothing here edits it. apply and check read the options and say which parts are missing. Add them in Steam, in the simulator's properties, before %command%:

WINEDLLOVERRIDES="version=n,b" PROTON_NVIDIA_NVCUDA=1 PROTON_DLSS_UPGRADE=1 DXVK_NVAPI_DRS_SETTINGS=ngx_dlss_fg_override=on %command%
  • WINEDLLOVERRIDES="version=n,b": Wine would load its own version.dll and never the file in the simulator's folder. If the line already has WINEDLLOVERRIDES, add version to it: names with the same mode go together, as in dxgi,version=n,b, and entries with different modes are separated by a semicolon.
  • PROTON_NVIDIA_NVCUDA=1: the mod takes the RTX 40 route only when CUDA answers with compute capability 8.9, and Proton leaves CUDA off without this. Proton FS2024 honours it. Without it the log has capability=0.0 verified=0 and route=pending ready=0.
  • PROTON_DLSS_UPGRADE=1: Proton then puts the newest DLSS frame generation in the prefix, and that is the copy the mod patches. The simulator's own nvngx_dlssg.dll stays as it is.
  • ngx_dlss_fg_override=on inside DXVK_NVAPI_DRS_SETTINGS, which takes a comma-separated list. If the line has that variable already, add this to its list.

Your other options can stay. The line the test ran with also had options for Wayland and HDR, and they are not part of this.

Fixed mode

The simulator asks DLSS frame generation for its dynamic mode. In the mod's default mode, "follow game", the mod passes that on without a target frame rate, and nothing is generated: the simulator's frame generation is on and the log still says presented=1, with Live-reapplied follow-game options: dynamic=1 in it. The mod only generates frames here in fixed mode.

The mod writes RTXMFG-Universal.json in the simulator's folder when it first runs. apply sets "followGame" to false and "mode" to "fixed" in it, changes no other byte, and when a key is missing it adds it. The multiplier is yours: change "multiplier" in the file, or pick it in the mod's menu. The mod reads the file again while the simulator runs. 3x is the multiplier measured here.

If the file doesn't exist yet, apply says to start the simulator once and run it again.

Start it

Turn DLSS frame generation on in the simulator's graphics settings. The mod's menu appeared by itself in the simulator's main menu on the test machine, and Backspace opens and closes it. The menu is where the mode and the multiplier change, and where the mod's other settings are.

The mod generates frames in flight and not in the menus. While the menu is up, the log stays at route=pending ready=0.

The DLSS 5 tab of the menu appears when nvngx_dlssnr.dll sits beside the simulator's executable. The DLSS 5 Neural Rendering guide says where that file comes from. The tab starts off. With the seventh patch it ran in Before and After upscaling on the test machine.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check mfg-unlocker

It prints ten lines, each starting with ok or FAIL, and changes nothing. Before the mod has run once and written its log, it prints eight:

  • the GPU the simulator uses is an RTX 40 series card, chosen the way the other tools of this repository choose it, through vulkaninfo;
  • version.dll in the simulator's folder is the patched file, by its sha256;
  • the launch options in Steam hold each of the four parts, one line for each;
  • "followGame" is false and "mode" is "fixed" in the config file, with the multiplier on the second line;
  • the mod's newest log, RTXMFG-flightsimulator2024-<hash>.log, has capability=8.9 verified=1, so the mod found the card through CUDA, and MFG_PROXY_UI state=active, so its menu installed. The earlier logs, named .previous.log, are not read.

The check can't see frame generation itself. For that, fly with it on and read the log:

SIM=$(~/flightsim-on-linux/bin/flightsim-on-linux machine --json | python3 -c 'import json,sys; print(json.load(sys.stdin)["sim_install"])')
grep 'State heartbeat' "$(ls -t "$SIM"/RTXMFG-*.log | head -1)" | tail -3

Working looks like route=local ready=1 ... control=fixed 3x gameFG=1 appliedFG=1 ... presented=3. With presented=1 nothing is generated yet.

Known problems

  • The first start after an install compiles shaders and stutters. Close the simulator and open it again before you judge.
  • Only ReShade 6.8.0 as dxgi.dll was tested, with AtmosphereMod, the Glass Cockpit DLSS Fix and RenoDX HDR loaded in it. Three of the seven patches (the factory's module path, the adapter-parent route and the module handle) exist because ReShade is the simulator's dxgi.dll. Without ReShade the install prints a note and goes on, and the result is untried.
  • The DLSS 5 tab and the add-on of the DLSS 5 Neural Rendering guide do the same job and must not run together. The tab starts off, so with dlssnr-linux.addon64 in the folder, leave the tab off. The test ran with that add-on removed.
  • The patch list is for release 1.7.0 only. A different file is refused.
  • A version.dll that another mod put in the simulator's folder blocks the install, and the check names its sha256.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo mfg-unlocker

With the simulator closed, this deletes version.dll when it is the patched file and leaves any other. It puts RTXMFG-Universal.json back as it was before the first apply. It then lists the files the mod made in the simulator's folder, RTXMFG-* (the config, the status file, the logs and the interval tables) and RTX40MFG-UI*.ini, and deletes none of them. Delete them yourself if you want them gone.

The launch options stay as they are. Take version out of WINEDLLOVERRIDES and the other parts out of the line yourself, unless something else uses them.
