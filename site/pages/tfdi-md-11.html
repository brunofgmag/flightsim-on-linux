title: TFDi Design MD-11 description: How to install and run the TFDi Design MD-11 in MSFS 2024 under Proton: the Install Manager, the NavData step that looks stuck and the command that finishes it natively, the Extended Simulation package, AIRAC through Navigraph Hub, and how to undo. ---

TFDi Design MD-11

Tested with the MD-11 package 1.1.32 and NavData 1.1.22 on 13 October 2026. The Install Manager works until it reaches the NavData, where it looks stuck. One command finishes that step. touches add-on files

That command, fix-navdata, changes three files: the package's layout.json, the Install Manager's installation.xml and its NavData_FS24.cache. Before it changes anything it copies the three to compatdata/2537590/flightsim-on-linux-backup/tfdi-md-11, in a folder named for the date and time. addon undo tfdi-md-11 puts them back as they were before the last run. installation.xml holds your activation code, so the copy holds it too. Never paste either file into an issue, a forum post or an AI chat.

Get it

The MD-11 asks for an activation code. You get the Install Manager, MD11InstallManager.exe, from your vendor account (TFDi Design). This guide doesn't have the download page. The Install Manager is a WPF program that runs on wine-mono, and it downloads and installs the aircraft packages. On the test machine the core package was 1.1.32.

Install it

Close the simulator and every other program of its prefix first, and run nothing else while the Install Manager works. The ground rules explain why. Then give it to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install tfdi-md-11 ~/Downloads/MD11InstallManager.exe

Without the file name it only prints where to get the program. With it, the command refuses to start while the simulator runs or any program is open in the prefix, and names those programs. Then it runs the Install Manager in the simulator's prefix. On 13 October 2026 the Install Manager did not run from a Bottles prefix, where it failed for lack of a window driver. The cause was not found. In the simulator's prefix it ran, and no Proton FS2024 patch was needed.

The Install Manager needs your activation code, and then it downloads the packages. The download bar is fine. The step that looks stuck is "Installing NavData_FS24". The NavData package holds about 94,600 small JSON files, and creating that many files through Wine's file layer is far slower than creating them natively, so the Install Manager crawls and looks frozen. When it stops at that step, close the Install Manager and run:

~/flightsim-on-linux/bin/flightsim-on-linux addon launch tfdi-md-11 fix-navdata

It refuses to run while the simulator or the Install Manager is open. Then it does these things in this order:

  • It finds the newest TFDi_Design_MD11.NavData_FS24.<version>.zip in the prefix's Temp folder, which is where the Install Manager downloaded it, and tests the zip.
  • It copies the three files aside, as above.
  • It unpacks the zip natively, with unzip, into the folder where the Install Manager's installation.xml says the FS24 packages go. If that path can't be found, it uses your Community folder.
  • It rewrites the NavData part of layout.json: it keeps every entry that is not under data/primary/ and lists the files now on disk, with their sizes and times.
  • It sets the NavData_FS24 version in installation.xml, adding the line if it is missing, and writes the cache file.

It prints each step and the number of files. The step recurs with each NavData update, because the Install Manager meets the same wall each time.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply tfdi-md-11

This changes nothing. The MD-11 needs no setting in the prefix and no Proton FS2024 patch. It was tested on Proton FS2024, and stock Proton was not tried.

The first time you load the aircraft, the simulator compiles its WASM module for about 4 minutes. That is normal, and the result is cached afterwards. Don't kill the simulator while it does, as the ground rules explain.

AIRAC

The AIRAC cycle for the MD-11 comes through Navigraph Hub, not through the Install Manager. The Hub unpacks the AIRAC with its own 7-Zip, inside Wine, and that is slow for the same reason as above. On the test machine the Hub's unpacker needed 27 minutes 31 seconds for the 97,203 files of the 2610 package, on 14 October 2026, and the native 7z unpacked the same package in 509 milliseconds. The Hub's guide has the stand-in for its procgov.exe that sends the unpacking to the native 7z. Two things to know: the Hub puts its own procgov.exe back when it updates itself, and after an AIRAC update the MD-11 button in the Hub can stay on INSTALL until you reopen the Hub, although the files are already in place.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut tfdi-md-11

This writes an entry called "MD-11 Extended Simulation" in your application menu, with the program's own icon when 7z and magick are installed. It opens the MD-11 Extended Simulation package. With the simulator closed it opens it in the simulator's prefix, and with the simulator running it opens it inside the simulator's container. With the package already open it says so and does nothing.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check tfdi-md-11

It prints three lines, each starting with ok or FAIL, and changes nothing. It lists the NavData files on disk, which took about a second for 95,000 files in a throwaway test folder:

  • installation.xml lists NavData_FS24, and the line gives the version;
  • the MD-11 package is in the folder that installation.xml names for FS24, or in your Community folder, and the line says which;
  • layout.json lists every NavData file that is on disk under Data/Primary. It may list more without failing: on the test machine it listed 95,578 and the disk held 4,658, and the cause was not traced.

The third line fails when the Install Manager stopped before it finished, because the files and the list disagree. Close the Install Manager and run fix-navdata.

Known problems

  • The NavData step stalls at each NavData update, and fix-navdata finishes it each time.
  • The first load of the aircraft compiles for about 4 minutes.
  • The Hub restores its own procgov.exe when it updates itself, and its MD-11 button can stay on INSTALL after an AIRAC update until you reopen it.
  • The Install Manager did not run from Bottles. The cause was not found.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo tfdi-md-11
~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut tfdi-md-11 --remove

The first command, with the simulator closed, puts layout.json, installation.xml and the cache file back as they were before the last fix-navdata. If the cache file did not exist before, it is deleted. Running it twice gives the same result. It does not delete the NavData files that were unpacked. Don't run it after the Install Manager has updated the package by itself since then, because it would bring back an older layout.json. The second command takes out the menu entry.
