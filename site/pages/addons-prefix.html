Add-ons prefix

Tested on 1 November 2026. A second Wine prefix for programs that only talk to the simulator over SimConnect. It has its own Wine server and shares the simulator's C: drive. One command makes it and one service keeps it up.

Why it exists

A Wine server serves one prefix, and a program started next to the simulator joins the simulator's server. Leaving that server costs three things: the SimConnect pipe, the list of processes, and access to the simulator's memory. SimConnect over TCP replaces the pipe. The sentinel covers the list of processes for a program that only asks for a name. Nothing replaces access to the memory, so that decides who can leave.

  • Volanta, Active Sky with ActiveSky Utils, vRAAS and Lorby Axis and Ohs run here.
  • MSFS AutoFPS, the ChasePlane bridge and REX Atmos Core read or write the simulator's memory, so they stay on its server.
  • BeyondATC and SayIntentions.AI also stay: they load code into the simulator to dock jetways for the AI traffic.

On 1 November 2026 a flight on the test machine ran the four programs of the first line in this kind of prefix, started by the machine's own scripts. The scripts here are a port of those, and have run against a fake simulator only.

Make it run

Close the simulator and every program in its prefix. addon apply needs MinGW-w64 (mingw-w64-gcc on Arch, gcc-mingw-w64-x86-64 on Debian and Ubuntu) to build a small program.

~/flightsim-on-linux/bin/flightsim-on-linux addon apply simconnect-tcp
~/flightsim-on-linux/bin/flightsim-on-linux addon apply addons-prefix
~/flightsim-on-linux/bin/flightsim-on-linux addon watcher addons-prefix

The second command makes the prefix in ${XDG_DATA_HOME:-~/.local/share}/flightsim-on-linux/addons-prefix if it isn't there, writes its SimConnect.cfg and builds desktop-holder.exe. The Volanta guide says what the prefix holds. The third writes a user service called flightsim-on-linux-addons-prefix.service and switches it on. It starts with your login session and keeps desktop-holder.exe running, with or without the simulator.

Install your programs in the simulator's prefix before you make this one. Its registry is a copy, and nothing keeps it in step.

Why the service

On 1 November 2026 the prefix came up broken twice, at 10:21 and 11:19, each time cold and at the moment the simulator opened. No program could open a window until the Wine server restarted. Volanta died with FATAL:ui\gfx\win\hwnd_util.cc:65] 1400, ActiveSky Utils with Error creating window handle, vRAAS in HwndWrapper..ctor, and the prefix had no explorer.exe /desktop.

Wine starts that explorer for the first window in a prefix. If it dies, the Wine server keeps a desktop with no explorer behind it, and every later program fails on that desktop until the server stops. Why explorer dies in the first second of the simulator was not found, and the fix doesn't depend on it. desktop-holder.exe is a hidden window and a sleep. With a window always open, explorer never exits, and nothing has to start it while the simulator opens. The one opening measured with the service on, at 11:58 that day, brought everything up by itself.

When the holder finds no desktop it exits with code 1, and its launch script restarts the Wine server of this prefix. The simulator has a server of its own, so that doesn't touch it.

Change Proton

The Wine server keeps the Proton it started with, and a newer Wine refuses to talk to it. After you rebuild or change Proton, close the programs of this prefix and run:

~/flightsim-on-linux/bin/flightsim-on-linux addon launch addons-prefix close

This stops the Wine server of this prefix and every program in it. With the service on, the prefix comes back in about 8 seconds on the new Proton. Restarting the service isn't enough: it uses KillMode=process, so that it can't take the programs down with it.

Make it again

A program you install in the simulator's prefix later isn't in this prefix's registry. To copy the registry again, close the simulator and the programs of this prefix, then:

~/flightsim-on-linux/bin/flightsim-on-linux addon watcher addons-prefix --off
~/flightsim-on-linux/bin/flightsim-on-linux addon launch addons-prefix close
FSOL_ADDONS_PREFIX_RESET=1 ~/flightsim-on-linux/bin/flightsim-on-linux addon apply addons-prefix
~/flightsim-on-linux/bin/flightsim-on-linux addon watcher addons-prefix

Whatever the add-ons wrote into the old registry is lost, so run addon apply again for each add-on that runs here. The copy refuses while a Wine server holds either prefix.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check addons-prefix

It prints seven lines and changes nothing: the prefix has its own registry, drive_c is the simulator's, .update-timestamp holds disable, SimConnect.xml declares a port above 1023, SimConnect.cfg points at it, desktop-holder.exe is built, and whether the desktop is being kept up. That last line never fails, because Volanta runs without the service. It says how to switch the service on.

Known problems

  • The prefix stays on all the time: one Wine server and about ten idle processes.
  • Don't run one program in both prefixes at once. The two Wine servers share the folder but not the file locks or the mutexes.
  • The first second of the simulator can still take down a program that opens with it. Watchers here wait about 20 seconds for that reason.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon watcher addons-prefix --off
~/flightsim-on-linux/bin/flightsim-on-linux addon launch addons-prefix close
~/flightsim-on-linux/bin/flightsim-on-linux addon undo addons-prefix

The first takes out the service, the second stops the prefix, and the third removes SimConnect.cfg. The prefix stays, because it holds the settings of the programs that run in it. addon undo prints the rm -r command that deletes it.
