title: iFly 737 MAX8 description: How to install and run the iFly 737 MAX8 and the iFly Manager in MSFS 2024 under Proton: the Manager's setup, the plugin entry it writes in exe.xml, what the check reads, and the errors that look wrong and are not. ---

iFly 737 MAX8 and iFly Manager

Tested with the iFly 737 MAX8 1.1.0.3 and the iFly Manager setup v107 on 16 October 2026. It installs as on Windows. Nothing in the prefix needed fixing, and apply changes nothing.

Get it

You get the iFly Manager setup, iFlyManagerSetup_v107.exe on the test machine, from your vendor account. This guide doesn't know whether the aircraft is paid or give the download page, so look in your account. The setup is a 32-bit Windows installer. The Manager it installs downloads and updates the aircraft.

Install it

Close the simulator and every other program of its prefix first, and run nothing else while the setup works. The ground rules explain why. Then give the setup to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install ifly-737-max8 ~/Downloads/iFlyManagerSetup_v107.exe

Without the file name it only prints where to get the program. With it, the command refuses to start while the simulator runs or any program is open in the prefix, and names those programs. Then it runs the setup in the simulator's prefix. The setup needed no patch, no override and no setting on the test machine. On 16 October 2026 the Manager landed in C:\ProgramData\iFlyManager at 21:12, and its aircraft zip was in the Manager's downloads folder at 21:13.

Then open the Manager (see "Start it"), sign in and let it download the aircraft, with the simulator closed. When it finishes, run the check below: it tells you whether ifly-aircraft-737max8 is in your Community folder. If it isn't, the check fails and names the file it could not read.

The Manager writes its own entry in exe.xml, the file the simulator reads to start add-ons with itself. It rewrites the formatting of that file, and it keeps the other entries.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply ifly-737-max8

This changes nothing, and then runs the check. The aircraft needs one thing outside the simulator, the plugin Data\Tool\737MAX_Plugin.exe in the aircraft's folder, started with the argument auto. It is a native C++ program, so the simulator can start it from exe.xml like on Windows, and no watcher is needed. On the test machine, on 16 October 2026, the plugin started about two minutes after the simulator, stayed running and opened the iFly EFB (iFly-EFB.exe).

The AIRAC comes from Navigraph, through Navigraph Hub. Its guide covers the stand-in that makes the unpacking fast.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut ifly-737-max8

This writes an entry called "iFly Manager" in your application menu, with the Manager's own icon when 7z and magick are installed. With the simulator closed it opens the Manager in the simulator's prefix. With the simulator running it opens it inside the simulator's container. With the Manager already open it says so and does nothing. Use the Manager to install or update the aircraft only with the simulator closed. The plugin starts with the simulator and needs no entry in your menu.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check ifly-737-max8

It prints two lines, each starting with ok or FAIL, and changes nothing, so you can run it with the simulator open:

  • Community/ifly-aircraft-737max8 has a readable manifest.json, and the line gives the version;
  • exe.xml has an enabled entry whose path ends in \Data\Tool\737MAX_Plugin.exe, and that file exists. The case of the path doesn't matter.

When the second one fails because the entry is missing, open the Manager and install the aircraft with it, so it writes the entry. If the entry has Disabled set to true, the simulator won't start the plugin.

Known problems

  • The Manager shows "Error creating shortcut". It is a NotImplementedException from wine-mono and harmless; the aircraft installs and runs.
  • The Manager rewrites exe.xml and changes its formatting. It keeps the other entries.
  • It isn't known whether the Manager unpacked the aircraft into Community by itself or a Community organiser linked it. The check works for both, as long as the link isn't broken.

Undo

addon undo ifly-737-max8 has nothing to restore, because apply changed nothing. Take out the menu entry with:

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut ifly-737-max8 --remove

The plugin entry in exe.xml is the Manager's own. Remove the aircraft with the Manager.
