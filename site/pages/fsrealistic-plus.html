title: FSRealistic+ description: How to install and run FSRealistic+ in MSFS 2024 under Proton: the installer, the entry in exe.xml that starts its service with the simulator, and what the check reads. ---

FSRealistic+

Tested with FSRealistic+ 1.1.9 on 14 October 2026. The installer needs nothing special, and the program starts from exe.xml like on Windows. apply adds that one entry.

Get it

You get the installer, FSRealistic_Plus_v1.1.9.exe on the test machine, from your vendor account (rkApps). This guide doesn't have the download page or the price. It is an Inno Setup installer. The package it installs is rkapps-fsrealistic, with the program in its service folder.

Install it

Close the simulator and every other program of its prefix first, and run nothing else while the installer works. The ground rules explain why. Then give the installer to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install fsrealistic-plus ~/Downloads/FSRealistic_Plus_v1.1.9.exe

Without the file name it only prints where to get the program. With it, the command refuses to start while the simulator runs or any program is open in the prefix, and names those programs. Then it runs the installer in the simulator's prefix. Nothing else was recorded as needed for it on the test machine.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply fsrealistic-plus

The program FSRealistic+ needs is service\FSRealistic-Plus.exe, in the package. It is a native C++ program, so the simulator can start it from exe.xml, like on Windows. (Programs written for WPF can't start that way, because a program started by the simulator inherits the simulator's environment, which turns Direct3D 9 on.) On the test machine the entry was added by hand, and the program ran on 14 and 15 October 2026. No Proton FS2024 patch is involved.

apply does this, with the simulator closed:

  • It looks in exe.xml, in the folder that holds UserCfg.opt, for an entry whose path ends in \rkapps-fsrealistic\service\FSRealistic-Plus.exe. If there is an enabled one, it says so and stops. If there is one with Disabled set to true, it leaves it as it is and says so.
  • If there is none, it refuses when the program isn't in your Community folder yet: install it first.
  • Otherwise it copies exe.xml to compatdata/2537590/flightsim-on-linux-backup/fsrealistic-plus, adds an entry called FSRealistic+ with the program's path, keeping the other entries, and creates the file if there is none.

Start it

You don't start it. The simulator starts it with itself, from exe.xml.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check fsrealistic-plus

It prints one line, starting with ok or FAIL, and changes nothing, so you can run it with the simulator open. It wants an enabled entry in exe.xml whose path ends in \rkapps-fsrealistic\service\FSRealistic-Plus.exe, and that file has to exist. The case of the path doesn't matter, and a path that goes through a link to the Community folder counts. It says what is wrong when there is no exe.xml, no entry, an entry with Disabled set to true, or an entry that points at a file that is gone. In the first two cases run apply.

Known problems

  • None are recorded. FSRealistic+ was seen running on 14 and 15 October 2026.
  • After a simulator that was ended by force, the programs it started from exe.xml, FSRealistic+ among them, stay open and hold Steam's "running" state of the game until they exit. On the test machine Steam released the game only when they were gone.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo fsrealistic-plus

This removes the entry that apply added, and deletes exe.xml only when apply created it. An entry that you or the installer wrote stays. The copy of the old exe.xml is in the backup folder above.
