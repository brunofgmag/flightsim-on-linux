title: simMarket description: How to run simMarket in MSFS 2024's prefix under Proton: the Electron option it needs, the notification stub it must not see, the menu entry that also closes it, and what the test machine did with a second GPU. ---

simMarket

Tested with simMarket 4.20.0 on 14 October 2026. It installs like any Windows program and needs one Electron option, which the menu entry gives it. Nothing in the prefix changes.

Get it

simMarket is a store for add-ons, an Electron program. Its Windows installer used here was simMarket-4.20.0.win-x64.exe, a Squirrel setup of about 158 MB. Where it is downloaded from isn't recorded here; get it from simMarket.

Install it

Close the simulator and every program in its prefix, and run nothing else while the installer works. The ground rules explain why. Then give the installer to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install simmarket ~/Downloads/simMarket-4.20.0.win-x64.exe

The command refuses to start while the simulator runs or any program is open in the prefix, and names those programs. It then runs the installer in the simulator's prefix. On the test machine the installer needed no setting of its own.

simMarket downloads the installer of a product into the prefix's Downloads folder and stops there; it doesn't run it. Close simMarket, then run that installer yourself, alone, as the ground rules say.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply simmarket

This changes nothing in the prefix, and then runs the check. The launch script gives simMarket two things:

  • --disable-gpu-sandbox, the Electron option that let it run on the test machine.
  • toaststub=d, which turns off a stand-in DLL for that one program. On 14 October 2026 simMarket opened, drew normally and then closed itself after the login. The log ends with a request for Windows.UI.Notifications.ToastNotificationManager and an invalid read at 0xFFFFFFFFFFFFFFFF inside simMarket.exe, with 0x80004001 (not implemented) in a register. That class is not Wine's: the prefix pointed it at C:\appresolver\toaststub.dll, a stand-in installed in July 2026 for .NET programs that crashed when the notification API didn't exist. The stand-in says the class exists and answers "not implemented" to several methods. The guess is that Chromium goes further into it than it would without the class and can't handle that answer. It was not separated from other causes. The override only matters on a prefix where a stand-in of that kind is registered. On any other it does nothing.

The override was not exercised for what it is meant to prevent: in the next three starts no notification was requested. On 17 October 2026 the log had two ToastNotificationManager lines and no Unhandled page fault. Whether toaststub=d reaches a DLL that the registry names by its full path was not measured either.

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut simmarket

This writes an entry called "simMarket" in your application menu, with simMarket's own icon when 7z and magick are installed, and a "Close simMarket" action. The entry starts the newest app-* folder's program in the simulator's prefix. With simMarket already open it says so and does nothing. The action asks all of simMarket's processes to end, the way a polite kill does, and never uses kill -9. Close simMarket before you start the simulator or run an installer, since a program left open in the prefix holds it.

With the simulator running, the entry starts simMarket inside the simulator's container with the same two settings. The test machine did not run it that way with only those: it has a second GPU, and there simMarket got the integrated Radeon card (the Vulkan loader's VK_LOADER_DRIVERS_SELECT set to *radeon*, and DXVK_FILTER_DEVICE_NAME and VKD3D_FILTER_DEVICE_NAME set to RADV) plus the Chromium options --in-process-gpu --disable-gpu --disable-gpu-compositing, to keep it off the card the simulator draws on. That is a choice for a machine with two GPUs, so the script leaves it out. If simMarket takes video memory from the simulator on yours, you can pass the Chromium options after the script name with addon launch simmarket launch -- --in-process-gpu --disable-gpu --disable-gpu-compositing. A plain start with the simulator open, without any of them, has not been measured.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check simmarket

It prints one line, starting with ok or FAIL, and changes nothing, so you can run it with the simulator open: simMarket is installed in the prefix, and the newest app-* folder is named.

Known problems

  • simMarket closed itself once after the login, in the notification stand-in described above.
  • Product installers are left in the prefix's Downloads folder, unrun.

Undo

addon undo simmarket has nothing to restore, because apply changed nothing. Take out the menu entry with:

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut simmarket --remove
