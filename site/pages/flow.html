title: Flow Pro description: How to install and run Parallel 42 Flow Pro in MSFS 2024 under Proton: the installer that needs an empty prefix, the two stand-ins for Windows components it shares with ChasePlane, and why the manager is opened through protontricks. ---

Flow Pro

Tested with Flow Pro 2026.44.2.7 on 28 October 2026. It needs the same two small stand-ins for Windows components as ChasePlane, and nothing else in the prefix. Whether it works in flight was never checked.

Get it

Flow Pro is made by Parallel 42. Where to buy it isn't recorded here. The installer on the test machine was Flow Pro.exe, version 2026.33.5.13 when it was installed; the package p42-util-flow-pro in Community is 26.44.2 now, and the manager that opens from it is Flow for MSFS2024.exe, 2026.44.2.7. The installer writes entries for the manager (Flow Manager) and for FlowShare in exe.xml, so the simulator starts both.

Install it

The prefix has to be empty: close the simulator and every other program, and run nothing else while the installer works. The ground rules explain why: on 13 October 2026 the ChasePlane installer ended with "Installation failed" and an access denied message while another program was open in the prefix, and with nothing else open ChasePlane and Flow both installed on the first try. Then give the installer to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install flow ~/Downloads/"Flow Pro.exe"

It refuses to start while the simulator runs or any program is open in the prefix, and names those programs. Nothing else is needed for the installer: no patch, no override. A package that is a Linux link in Community blocks it; Installing add-ons says why and what to do.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply flow

Close the simulator and the manager first. This is the part of the ChasePlane fix that Flow shares, and the two add-ons keep one copy of it. The command builds two small programs on your machine, copies them to C:\appresolver in the prefix and registers them:

  • AppResolverShim.dll, a stand-in for the Windows COM class CAppResolver. The notification library that Parallel 42 programs use asks that class for the application id of the process, Wine doesn't have it, and the program stops in the constructor of its window. The stand-in answers with the name of the process. It needs the .NET SDK to build (dotnet-sdk on Arch, dotnet-sdk-8.0 on Debian and Ubuntu), or else the compiler in Proton's wine-mono, run through Wine in your prefix.
  • toaststub.dll, a stand-in for the WinRT class Windows.UI.Notifications.ToastNotificationManager, which Wine doesn't implement either. It answers with a notifier that does nothing. It needs x86_64-w64-mingw32-gcc to build (mingw-w64-gcc on Arch, gcc-mingw-w64-x86-64 on Debian and Ubuntu).

Flow needs no Proton patch of its own and no Steam launch option. If you also use ChasePlane, the ChasePlane page has the patches that matter for it.

Start it

The simulator starts the manager from exe.xml. For a manager you open yourself, with the simulator closed:

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut flow

This writes an entry called "Flow Pro" in your application menu, with the manager's own icon when 7z and magick are installed. With the simulator closed it runs wine <manager>; wineserver -w through protontricks -c. Since 2026.44.2.7 the manager copies itself to Temp\Parallel 42\Managers\ inside the prefix and exits, and protontricks-launch kills that copy when the first process returns. Waiting for the Wine server keeps the container, and the copy, alive. With the simulator open, the entry starts the manager in the simulator's container instead. There is no watcher: the manager and FlowShare run from exe.xml.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check flow

It prints two lines, each starting with ok or FAIL, and changes nothing, so you can run it with the simulator open:

  • AppResolverShim.dll is in C:\appresolver and registered for the CAppResolver class;
  • toaststub.dll is there and registered for the ToastNotificationManager class.

Known problems

  • Using Flow inside the simulator was never checked.
  • An installer or an update rewrites exe.xml.
  • The stand-ins date from July and were not measured again with each Flow build; a new build can ask Windows for something else.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut flow --remove
~/flightsim-on-linux/bin/flightsim-on-linux addon undo flow

The first takes out the menu entry. undo removes the two stand-ins and their registry entries unless ChasePlane still uses them, in which case they stay until you undo that too. A stand-in that was already in C:\appresolver before the fix is put back.
