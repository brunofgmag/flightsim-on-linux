title: Contrail description: How to run Contrail in MSFS 2024's prefix under Proton: the winhttp stand-in that gets it past the splash screen, Direct3D 9 off, the menu entry that also closes it, and what happens when Contrail updates itself. ---

Contrail

Tested with Contrail 2.4.6 on 14 October 2026. It installs like any Windows program, but it stays on its splash screen without a small stand-in for winhttp.dll placed next to it, so this fix adds files to the add-on's folder.

touches add-on files The fix adds two files, winhttp.dll and winhttp_wine.dll, to the newest app-* folder of Contrail in the prefix. If that folder already had a winhttp.dll of Contrail's own, it is kept in compatdata/2537590/flightsim-on-linux-backup/contrail. This takes both files out and puts a kept file back:

~/flightsim-on-linux/bin/flightsim-on-linux addon undo contrail

Get it

Contrail is a store for add-ons, written in WPF on .NET 6. Its installer for Windows is ContrailSetup.exe, a Squirrel setup of about 147 MB. Where it is downloaded from and what it costs aren't recorded here; get it from Contrail.

Install it

Close the simulator and every program in its prefix, and run nothing else while the installer works. The ground rules explain why. Then give the installer to the CLI:

~/flightsim-on-linux/bin/flightsim-on-linux addon install contrail ~/Downloads/ContrailSetup.exe

The command refuses to start while the simulator runs or any program is open in the prefix, and names those programs. It then runs the installer in the simulator's prefix. On the test machine the installer needed no setting of its own.

Contrail's products are another matter. It downloads the ones that come as an installer .exe into C:\users\steamuser\Downloads in the prefix and stops there; it doesn't run them. Close Contrail, then run each installer yourself, one at a time, as the ground rules say. The products that come as zip files it unpacks by itself.

Make it run

~/flightsim-on-linux/bin/flightsim-on-linux addon apply contrail

Contrail 2.4.6 opened its window for choosing the simulator and, once MSFS 2024 was chosen, stayed on the splash screen. The process stayed alive and the main window was never created. In a trace, the .NET WinHttpHandler asks for the images of the store (cdn.contrail.shop) and calls WinHttpAddRequestHeaders with a string that holds only a line break. Windows accepts that call and does nothing. Wine 11 answers with error 12153, ERROR_WINHTTP_INVALID_HEADER, and .NET raised that exception in a loop, 230 more in ten seconds.

Two things change that, and the launch script does both every time:

  • A winhttp.dll stand-in, built on your machine with MinGW, goes next to Contrail.exe. It passes 48 functions on to a copy of Proton's own winhttp.dll, named winhttp_wine.dll, and implements only WinHttpAddRequestHeaders: it strips the line breaks at the start and answers success when nothing is left. Contrail is started with winhttp=n,b, so the copy next to it loads first. With the stand-in, the warnings and the exceptions dropped to zero and the main window appeared. Without it, in the same session, only the splash screen. A copy next to the program is enough because winhttp is not on the prefix's list of system-only DLLs; ole32 is, which is why the TriTriSim Hub needed a different way.
  • Direct3D 9 is turned off for Contrail with d3d9=d. Outside the simulator's container the WPF window didn't crash, but DXVK couldn't get a Vulkan swapchain (VK_ERROR_INITIALIZATION_FAILED), fell back to presenting through GDI, and the window came out with black rectangles. With Direct3D 9 off, WPF draws in software and the window is whole.

Contrail's updater, Squirrel, makes a new app-* folder for each version, so the launch script copies the two files into the newest one on every start, and apply does the same by hand. On the test machine Contrail updated itself from 2.4.6 to 3.0.0 on 22 October 2026. The test machine's own launch script found the new folder and the two files were in it, but the fix was measured on 2.4.6, and 3.0.0 hasn't been tested as a version of its own. Starting Contrail with the simulator running, inside its container, hasn't been run either.

The stand-in needs x86_64-w64-mingw32-gcc: install mingw-w64-gcc (Arch), gcc-mingw-w64-x86-64 (Debian, Ubuntu) or mingw64-gcc (Fedora).

Start it

~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut contrail

This writes an entry called "Contrail" in your application menu, with Contrail's own icon when 7z and magick are installed, and a "Close Contrail" action. The entry copies the two files, then starts Contrail in the simulator's prefix. With the simulator running it starts Contrail inside the simulator's container, and with Contrail already open it says so and does nothing.

The window's X doesn't close Contrail. After clicking it, the window stayed visible on the test machine, because the title bar belongs to the MahApps library and the click doesn't reach it. The action asks all of Contrail's processes to end, the way a polite kill does, and never uses kill -9. Close Contrail this way before you start the simulator or run an installer, since a program left open in the prefix holds it.

Check it

~/flightsim-on-linux/bin/flightsim-on-linux addon check contrail

It prints two lines, each starting with ok or FAIL, and changes nothing, so you can run it with the simulator open:

  • the newest app-* folder has the winhttp.dll stand-in built from this repository;
  • winhttp_wine.dll in it is the winhttp.dll of the Proton in use.

After a Contrail update the first line fails until Contrail has been started from its menu entry once, or apply has run. After a Proton rebuild the second one can fail, and the same two ways fix it.

Known problems

  • The window's X doesn't close Contrail. Use the menu action.
  • Product installers are left in the prefix's Downloads folder, unrun.
  • Contrail 3.0.0 and the start inside the simulator's container are expected to work and haven't been tried as separate tests.

Undo

~/flightsim-on-linux/bin/flightsim-on-linux addon undo contrail
~/flightsim-on-linux/bin/flightsim-on-linux addon shortcut contrail --remove

The first removes the two files from every app-* folder and puts back a winhttp.dll that Contrail shipped, if there was one. Until you apply the fix again, Contrail stays on its splash screen. The second takes out the menu entry.
